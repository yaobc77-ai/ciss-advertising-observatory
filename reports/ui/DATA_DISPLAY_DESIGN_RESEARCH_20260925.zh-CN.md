# 数据展示设计研究：Advertising Observatory

研究日期：2026-09-25。状态：设计建议，尚未应用到网页。

本轮搜索第一方设计指南，查看 OWID、ProPublica 的实际页面，并对照本机 Data 页和现有 CSS。目标是改善记者、研究者和律师查数、比较、查看原文的体验。

## 1. 建议的方向

采用**研究出版物的排版 + 数据探索工具的交互**：清楚的标题、克制的颜色、有主次的图表、可查询的表格，以及与数字相邻的来源说明。

Query 保留此前确定的 INDRA 式集中入口。Data 用更适合阅读和比较的布局，不必沿用 Query 的大面积空白。

三个判断标准：

1. 进入页面后，能看懂当前数据范围和主要研究问题。
2. 不依赖悬停，就能读出关键数字、名称和单位。
3. 从一个统计数字进入对应记录，再查看原文，路径连续，筛选条件保留。

## 2. 精选参考：各取所长

### A. Our World in Data：一个图表就是一个完整的研究单元

[实际图表页](https://ourworldindata.org/grapher/co-emissions-per-capita)

**本轮观察：**图题和指标定义在图上方；图表是主区域，选择器在右侧；图下有来源、下载和分享；详细方法放到后续区域。曲线末端直接标名称，减少寻找图例的往返。

**迁移到本项目：**每个分析视图统一为“研究问题 → 当前范围/计量单位 → 图/表 → 来源与下载”。图和表共享同一选中集合；详细方法可展开。

**取舍：**不照搬 CO₂ 页的时间控件、地图和多种图型。我们的广告数据需要先确认采集覆盖，年度记录量不能直接解释为整个广告市场的趋势。

### B. ProPublica Nonprofit Explorer：让记录值得阅读

[数据入口](https://projects.propublica.org/nonprofits) · [实体详情示例](https://projects.propublica.org/nonprofits/organizations/142007220)

**本轮观察：**大标题、简短说明、更新时间和搜索组成清楚的入口。实体详情以名称和身份信息起头，随后给摘要与小图；年度明细将年份、精确数字、原始申报文件链接并排放置。

**迁移到本项目：**记录标题作为主要链接；日期、媒体、赞助方作为次级信息；正文和附件进入详情。将重复的“View record”操作列整合进标题，保留原文和归档状态。

**取舍：**实体详情适合深入阅读，长篇实体档案不应全部堆进 Data 总览。用户不必先滚过所有图表才能找到记录。

### C. Financial Times Visual Vocabulary：根据研究问题选图

[官方图型词汇表](https://github.com/Financial-Times/chart-doctor/blob/main/visual-vocabulary/README.md)

**来源要点：**将图型按排名、分布、时间等表达目的组织，帮助编辑选择合适的视觉表达。

**迁移到本项目：**公司/媒体数量用排序横条；年度记录数用柱图；公司 × 媒体的精确查数用带数值矩阵。关系图负责探索连接，不承担所有精确比较。

### D. Datawrapper：把基础图表和表格打磨好

[图型选择](https://www.datawrapper.de/blog/chart-types-guide) · [表格设计](https://www.datawrapper.de/blog/guide-what-to-consider-when-creating-tables) · [色彩层级](https://www.datawrapper.de/blog/emphasize-with-color-in-data-visualizations)

**来源要点：**图表适合看模式，表格适合查询精确值；颜色可以引导注意力；图型应服务于要表达的问题。

**迁移到本项目：**默认同一组横条使用同色，选中项才强调；文字左对齐，数字右对齐；数值直接标出；矩阵把精确数字与浅色底纹结合；避免重复的边框与装饰。

### E. 小多图：作为后续比较工具

[Datawrapper 小多图指南](https://www.datawrapper.de/blog/what-to-consider-when-creating-small-multiple-line-charts)

**来源要点：**把多个系列拆为小图可减少重叠，但图太多会造成长页面，比较时还需要留意坐标尺度。

**迁移到本项目：**将来比较少数赞助方的年度记录数时，可以用共享坐标的小柱图。首版不为所有赞助方生成一整墙图。

### F. FEC：把筛选后的记录集合放在工作区中心

[Individual contributions](https://www.fec.gov/data/individual-contributions/)

**本轮观察：**侧栏筛选、当前条件、结果规模、导出和表格组成一个工作区。记录可在行下展开更多字段，原始申报影像与实体详情有直接入口。已查看实际截图和行内展开。

**迁移到本项目：**Records 视图常显赞助方、媒体、年份，以及可清除的已选条件。主表突出标题、赞助方、媒体、日期、来源；展开或进入详情时保留筛选与分页。

**取舍：**本项目可给精确计数，无需复制其巨大数据集上的近似结果数或大量领域字段。侧栏只在空间足够且用户需要持续调整条件时使用。

### G. ICIJ Offshore Leaks：围绕选中的实体展示关系

[实体示例](https://offshoreleaks.icij.org/nodes/10179083) · [第一方使用指南](https://offshoreleaks.icij.org/pages/howtouse)

**本轮核对：**实体页列出身份、来源、日期及分组关系表；官方指南说明搜索实体后可进入关系图并继续探索相邻实体。已读取实体页元数据与关系表；图交互依据指南，未逐项实测。

**迁移到本项目：**选中一个赞助方后，查看它涉及的媒体；关系图与文字关系列表并存，任何边都能回到对应广告记录。

**取舍：**本项目的边只代表来源中赞助方与媒体配对下的记录数，不代表所有权、资金、共谋或广告主张真实性。不能用视觉复杂度暗示尚未拥有的关系证据。

## 3. 对现有页面的具体判断

以下是本轮本机页面与 CSS 的观察，不是对参考网站的评价：

| 现状 | 影响 | 设计建议 |
|---|---|---|
| 四张图使用相近尺寸、相同边框卡片 | 主次不明显 | 一个主分析区域；辅助信息缩为摘要或切换视图 |
| 历史标签很长，条末数值有竖排 | 阅读费力，图面被压缩 | 标签图使用足够宽度和按行数计算的高度；数值水平外置 |
| 网络、热图、完整交叉表顺序堆叠 | 重复、长滚动，难比较 | 关系分析区域提供 Matrix / Network / Table 切换 |
| 筛选藏在 Tools | Data 页的分析范围不直观 | Data 露出常用筛选和已选条件；Tools 保留高级操作 |
| 当前记录表有很多独立操作/元数据列 | 标题与正文入口失去重心 | 标题优先；来源、日期、赞助方常显；采集词与技术信息放详情 |
| 所有图都使用强深蓝 | 每张图的每个元素都在争取注意 | 全局概览保持同色；选择比较对象时才建立强调层级 |

保留当前做对的部分：条末数字、年度柱图、Unknown 单列、赞助方规范显示、完整交叉表导出、来源详情入口。此次改善不需要重做这些数据能力。

## 4. 推荐页面结构

顶层仍为 Query / Data。Data 内采用三个视图，默认进入 Overview：

```text
Advertising Observatory                         Query  Data  Tools

Explore the collection
一句话介绍 + 数据版本/更新信息

Collection   Sponsor   Publisher   Year   More filters
已选条件 / Clear filters                 当前记录数与缺失说明

Overview                 Relationships                 Records

Overview
  Who appears as a sponsor, and where were the ads published?
  [ 带数值的矩阵：主要分析区域 ]            [ 选中项摘要 ]
  [ Chart / Table ]                       [ View records ]
  来源 · 单位 · 当前筛选范围 · Download

  [ 年度记录分布 ]                         [ 历史标签分布入口 ]

Relationships
  [ 选择公司/媒体、重置 ]
  [ 局部二部网络，点击后保持稳定 ]           [ 对应记录列表 ]
  完整范围 / 当前绘出范围 / 连线定义

Records
  [ 搜索、排序、导出、当前范围 ]
  Title                         Sponsor   Publisher   Date   Sources
  可点击标题 → 正文 / 原文 / PDF / 截图 / 技术信息
```

这是建议的信息架构。Overview 的矩阵回答客户的公司 × 媒体问题；Relationships 的网络支持沿关系查证。两处共用聚合结果和选择状态，不另造一套计数逻辑。

在窄屏上，侧栏移到图下；矩阵可局部横向滚动并固定行名，页面本身不横向溢出；记录页可转成紧凑的标题列表。网络保留列表/选择器入口。

## 5. 建议的视觉规则

这些是针对本项目的设计提案，尚未做视觉验收或对比度测试：

| 元素 | 建议 |
|---|---|
| 整体 | 保留黑色导航；正文区域接近白色，减少灰底套白卡的层数 |
| 标题 | 页面标题约 32–36px；图题约 20–24px；可试仅研究标题使用 Georgia，导航和数据保留系统无衬线字体 |
| 正文与图中文字 | 正文约 15–16px；图中名称/数字约 13–14px；技术长标识继续折叠 |
| 对齐 | 统一左边线，正文和图题对齐；数字用等宽数字形式，表格数值右对齐 |
| 色彩 | 深蓝表示主要数据/选中项；灰色表示非焦点；琥珀色用于缺失/需注意状态，并附文字说明 |
| 比较 | 未选焦点时同类数据同等对待；选择后其他项淡化，保留可读标签 |
| 容器 | 以留白和细分隔线组织章节；只在有独立交互边界时使用完整卡片 |
| 图表 | 横条从零起点；数值尽量水平直接标注；长名称换行；图高随类别数增长 |
| 矩阵 | 显示真实计数；零与缺失状态区分；提供图例、总计和可导出表格 |
| 动态反馈 | 选中行/节点的强调、明确加载状态；优先保持用户正在比较的布局稳定 |

避免用红/绿颜色暗示广告真假；历史自动标签与经人工确认的字段要有清楚区分。

## 6. 暂不采用的展示方式

- 默认展示所有节点的力导向大网图：本项目首先需要查数和回到原文，网络可聚焦展开。
- 用 Sankey 暗示赞助金额流向：目前连线只有记录数量，没有资金流证据。
- 词云作为主题答案：频率不能代替已定义的主题或可核对证据。
- 用时间连线暗示连续市场变化：先说明采样/采集范围，再讨论趋势。
- 大量彩色 KPI 卡片、环形图、渐变和阴影：当前研究任务不需要这些额外视觉层次。
- 自动生成“洞察结论”充当图题：先用中性的研究问题标题，结论需要数据与口径支持。

## 7. 下一步最小改造顺序

1. 确定 Data 的 Overview / Relationships / Records 分层，以及始终可见的当前筛选范围。
2. 统一标题、图中文字、横条标注、网格线和图表间距；修正长标签与竖排数字。
3. 合并矩阵/表格的展示，避免重复；将网络的记录详情移动到近旁。
4. 用真实的长公司名、零结果、多选、大量类别和窄屏检查布局；验证图表点击后的集合与导出一致。

优先复用现有 Dash、Plotly 和表格组件。以上工作主要是布局、图表样式和状态组织，无需因为视觉改版引入新的前端框架。

本轮未修改应用源码、数据库或部署，也未调用付费模型。
