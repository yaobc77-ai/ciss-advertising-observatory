## 网络计数与来源含义

- 节点直接使用当前来源中的 sponsor、publisher 字段；显示别名不自动合并身份。CERAWeek、协会、未知值保留各自口径。
- 连线表示相同字段组合下的广告记录数，可以追到具体文章。广告中提及一家公司不自动变成赞助关系。
- 默认只画前 24 条高计数关系，可改为 12、24、60。当前概览共有 36 条关系；默认图显示 24 条、覆盖 251 / 263 条可统计记录。未绘出的关系可用 Focus 下拉选择，覆盖量明确显示。
- 网络焦点只改变网络与对应记录列表，不修改页面整体统计或 RAG 范围。Tools 的集合筛选则共同约束它们。
- 图节点、数字与文章来自数据库；没有模拟关系或以模型补齐缺失字段。

1. **完整工程回归**：`pytest -q -m "not live" tests eval/client_review_20260925/test_prepare_client_review.py`：505 passed，73.70 秒。包含真实 PostgreSQL 测试，测试写入限定为 `obs_test`，新增迁移／聚合测试使用隔离 schema。后续焦点保留修正定向 UI 回归 63 passed。最后的 ID 与过期分页补丁验证另见文末补充。
2. **真实语料对账**：SQL 汇总与原 Python 汇总、交叉表、历史标签和年度分布逐项相等。第一页 20 条，第二页与第一页不重叠。默认可统计 263、可检索 226、未知日期 22、关系 36。记录见 [只读验证 JSON](meeting_prototype_validation_20260925.json)。
3. **浏览器操作**：验证组织筛选、15 条记录的第二页、3 条连线的来源列表和表格 21–40 / 263；浏览器错误日志为空。390 像素窄屏下页面主体无横向溢出，网络画布可在自身容器内滚动，另有下拉入口。
4. **数据迁移**：应用前建立本机备份；应用后 schema version=2，原始记录数、source_data_version、索引版本和 556 块保持一致。此证据针对本轮未改变原语料／索引，不等同于全库备份恢复验收。
5. **客户评价工具**：实际执行返回 pending，列出审阅人、批准记录、问题／金标准、文章分组等缺口；没有调用数据库或模型来掩盖材料缺失。

一次本机 dashboard 请求耗时约 390 ms，仅是这次 263 条可统计记录上的观测，不是并发测试、P95 或性能承诺。本轮未调用付费 API；未生成／重算向量，也未导入新的广告记录。
