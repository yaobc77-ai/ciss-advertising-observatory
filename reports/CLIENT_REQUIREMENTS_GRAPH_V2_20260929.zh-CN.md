# 客户六项研究问题：图谱详情改版前复核

日期：2026-09-29。范围：当前本机代码、既有计数回执和客户转贴邮件；本报告是本轮改版的需求审计，不是完成回执。没有运行付费模型、修改来源数据、推送 GitHub、部署 Railway 或联系客户。

## 本轮应完成什么

客户最关心的路径应直接可见：**选公司／所列赞助方 → 看全部媒体、数量和占比 → 打开对应文章**；反向路径是 **选媒体 → 看全部所列赞助方、数量和占比 → 打开对应文章**。最新用户明确要求图谱点击后显示具体饼图，因而本轮适合增加真实分母的环图，同时保留完整数量表。多家公司和媒体的比较继续使用已有完整矩阵；环图回答单个对象内部构成。

来源实体、关系、图例与详情需要让非技术用户读得懂。参考图中的支持／反对／中立来自政治游说语义，本项目的元数据没有这种字段，不能套用。颜色可以区分节点类型和占比类别；关系仍说明为来源记录共同列出名称。

### 最新 Query 费用与接口口径

上轮 Michelle 报告里的“固定句式数据库统计免费”是当时基础实现。当前本机启用模型辅助选工具，**问题理解有模型费用，即使之后只是 SQL 计数**；Data 的筛选、统计、图谱和记录浏览不调用模型。网页内部使用 Responses function calling；单独的 stdio MCP 服务复用同一工具执行器。这两个传输接口不能混称。

现有 MCP 图谱邻域工具只返回最多五篇选定原生文章的分页来源图。它有自己的覆盖范围，不能把该结果宣传成已经自动升级到全库 290 节点的界面大图。

## 可直接落实的详情契约

### 1. 选择赞助方／媒体

- 标题包含规范显示名、来源实体类型和当前筛选范围。
- 数量写为本集合合格记录，包含没有可检索正文的记录；正文可检索数另列。
- 赞助方环图按媒体分配；媒体环图按来源所列 sponsor 分配。每个扇区的名称、数量与占比都可在完整表中读取。
- 分母必须是该节点的全部合格记录。来源字段缺失时保留“未记录赞助方／媒体”的类别，不能只用已形成汇总线的记录重新归一化。
- 图谱不建立共同的 Unknown 企业节点；缺失类别是数据状态，可以存在于占比表和记录结果中。
- 选择切片或完整名单中的一项后显示交叉数量及对应文章，提供返回该节点全部文章的操作。

### 2. 选择汇总关系或文章

- 汇总线展示“两端名称共同出现于多少条来源记录”，绑定每条记录和版本，以及两条原始文章字段边的见证。
- 在需要提供百分比时，明确分别采用哪个端点的记录总数；不能把 5／15 与 5／18 混称一个占比。
- 文章路径中的 `source_lists_sponsor` 表示记录列出该赞助方，`published_in` 表示记录的媒体字段。方向和说明不能暗示资金流、控股、背书或事实核查。
- 文章标题进入正文／来源详情。存在原文链接、已核验材料、未核验候选和缺材料是不同状态；不要将全部候选 PDF 当成可确认档案。

### 3. 保留完整性与可访问性

- 数量表和键盘名称选择是图谱／饼图的等价入口；重要含义不能只用颜色、鼠标悬停或线粗细表达。
- 点选仅改变焦点和相邻详情；分页不改变图形布局或统计分母。修改全局筛选后旧选择不得继续显示旧数据。
- 圆环只适用于互斥元数据类别构成。历史多标签使用条形图／计数表，且说明类别可重叠。
- 所有点选由规范实体／边 ID 回到服务器可信当前范围；不信任浏览器传回的数量、标签、记录成员或任意 URL。
