# CLAIMS 来源关联与结果适配

## 已完成

新增 `observatory claims-audit`，复用已有 Python／SQLite／PostgreSQL 和分类文件，无新增依赖。工具只读两套数据库，不执行上游 Notebook，不调用模型，不发布标签。

实际读取 810 个输入段落、806 条保存结果和 828 个当前／历史正文版本。806 条结果都能准确回到输入行；`410、525、580、702` 没有保存结果，保留为未处理。

| 实际检查 | 严格文本／空白匹配 | 明确启用上游字符转换 |
|---|---:|---:|
| 全部保留段落可顺序对应的当前文章候选 | 1 | 8 |
| 当前正文可用范围内的唯一段落候选 | 0 | 84 |
| 唯一定位且关联全部保留段落的分类引文候选 | 0 | 37 |
| 引文唯一定位、但文章关联仍不完整的分类候选 | 239 | 289 |
| 回到原始正文直接核验的引文位置 | 840 | 1,109 |
| 错误字符位置 | 0 | 0 |

严格检查中的唯一文章候选不在允许检索范围内。表中数量是关联和定位结果，不能解释为广告数量、正确分类数量或已证实漂绿数量。

转换规则来自实际 Notebook：标点替换、Unicode 分解、有损 ASCII 转换及空白折叠。新实现保留每个字符在原文中的映射，不沿用清洗文本的坐标；删除字符造成多种边界时保留所有候选。只有显式选择 `--projection upstream-ascii-v1` 才启用，并绑定 Notebook 哈希和 Unicode 版本。

## 已发现的问题

- 保存的分类经过“创建／匹配／更新”操作，扁平列表丢失了每个分类与引文的对应关系。新适配器从原始响应中按操作和 JSON 位置保留 762 个分类候选。
- 199 条保存行是结构清楚的候选；605 条需复核；2 条含多个 JSON 块，隔离处理。443 条没有可复核分类，不能解释为无此类主张或阴性结果。
- 66 个分类候选的引文不在它自己的输入段落中，不能到别处找一句话来替它补证据。
- 71 个分类候选的原响应父类与最终映射冲突；部分定义在处理过程中变化。保留历史定义和当前候选定义，不把它们当成同一版本。
- 多数输入无法完整对应当前正文。已定位的局部证据与完整保留输入关联分开；缺失原文、历史版本、重复位置和已排除区间均保留状态。
