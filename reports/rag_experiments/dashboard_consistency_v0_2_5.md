# Dashboard 同次刷新的一致性 — 0.2.5

2026-09-16。修复两个 M3 问题，同时核对当前快照的备份恢复。数据仍为 `5114ebc1cf9afe59cdaa715e3ea45166`，275收录、263可计数、226可检索、558块。检索、生成、题库及源数据均未改变，本轮没有付费API调用。

## 改动与原因

1. **明细与图表共用一次查询。** 旧 callback 先 `service.browse(filters)` 取明细，再 `service.statistics(filters)` 再次读库。若导入在两次读取之间提交，页面可能混用新旧数据。现在一次读取的原始公开记录直接交给已有 `service.summarize`，同批记录再转换成表格展示字段。
2. **未知日期不作为月份绘图。** `_timeline` 排除 `Unknown`/`(Unknown)`；未知数仍保留在汇总卡片。全部日期未知时显示 `No dated records in this selection`。共享统计输出中的未知分组仍保留，便于其他查询对账。

统计必须先于 `_public_rows` 的展示转换：后者把空日期写成显示文字，不能再拿它判断真实日期是否缺失。改动只涉及 [app.py](../src/observatory/app.py)，复用已有统计函数，无新增服务、查询或依赖。

此修复保证一次 callback 内的明细与图表一致。稍后的导出和搜索按提交时的同一组筛选条件重新查询；维护期间发生数据更新时，它们仍可能读取较新的版本。页面没有新增跨请求冻结快照功能。
