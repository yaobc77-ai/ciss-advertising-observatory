## 改了什么

此前运行 `532453a7c43740ecbe5f4954d3522f41` 中，dev-03 的英语问题得到西语回答，dev-04/05 得到法语回答；引文定位校验没有发现这些问题。原运行及 [AI 复核](assisted_semantic_review_v0_2.md) 保留。

现在复用 [Lingua 2.2.0](https://pypi.org/project/lingua-language-detector/2.2.0/) 做本地语言检测，模型仍是 `gpt-5.6-luna`。库支持 75 种语言，具有 Python 3.12 的 Windows wheel，下载后无需语言检测 API。安装实际下载约 162.2 MiB；官方说明模型在磁盘约 300 MB，FST 结构改善运行内存。因此这不是小安装包，但避免维护自制语言分类器或增加模型调用。[发布说明](https://github.com/pemistahl/lingua-py/releases/tag/v2.2.0)

采用单例、默认精度与延迟加载。识别库及其版本已进入 `pyproject.toml`、`uv.lock`，环境由 uv 管理。PostgreSQL 与 pgvector 已在项目独立环境内，无需用户再下载安装。

处理路径为：

```text
问题 → 本地语言提示 → system 中写明目标语言 → 一次生成
     → 结算费用并保存原始结构化输出 → 引用校验 → 逐条及合并语言检查
     → 匹配或不确定：返回回答与记录；明确错语：保留证据、隐藏生成回答
```

只检查 `claim.text`。引用正文、文章标题和证据卡片不混入检测，英文原文可支持中文说明。应用规则由高优先级消息给出，问题和广告正文继续作为输入资料处理。[OpenAI 官方消息与指令说明](https://developers.openai.com/api/docs/guides/prompt-engineering#message-roles-and-instruction-following)

错语返回 `service_unavailable / answer_language_mismatch`，不是资料不足，也不自动重试。已结算生成费与查询 embedding 费保留，过滤后的原文证据仍可查看。数据库中保存未经修正的结构化输出，不声称保存了供应商完整原始响应。

## 判断边界

- 少于 20 个 Unicode 字母，或前两候选分数差低于 0.20，记为不确定。这是工程阈值，未经概率校准。
- `CCS?` 曾被库高分判断为匈牙利语，因此短文本不直接采用最高分。短中文也不强制为英语；提示仍要求按问题语言回答，仅在语言确实不清楚时使用英文界面默认。
- 不确定结果仍可展示，审计为 `inconclusive`，不能计作 `match`。库外语言、混合语言、长英文标题夹中文问句仍可能误判。
- 界面、SQL 计数、资料不足与服务状态提示目前为英文；本次约束针对生成的说明文字。
- 单条和合并文字分别检查，不能用大段英语掩盖另一条法语论断。语言匹配与证据语义支持、广告说法真实与否是三个不同问题。
