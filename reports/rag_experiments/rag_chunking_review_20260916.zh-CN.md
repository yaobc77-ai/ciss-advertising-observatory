# RAG 切分审查与候选实现

> 历史候选实现记录（2026-09-16）。下文“主库继续使用旧 558 块”描述当时状态；2026-09-17 已在 [0.3.0](release_v0_3_0_20260917.zh-CN.md)有意启用 556 块句界索引。原比较结果保留，不改写为新模型性能。

日期：2026-09-16。目标是改善现有广告证据问答的检索上下文和引用输入，服务 FA26 Dashboard / RAG 交付。本文不把引用可定位当作回答正确，也不把旧开发题上的结果当作独立验收。

## 1. 本轮范围

核对用户提供的审查；保留旧切分作为默认，增加可选句界切分；在引用目录内部合并相同原文版本的连续片段，保留原有 evidence ID；增加只读检索对比工具。主库当前 558 个片段作为基线，未重导或重算向量，未调用生成模型。

本轮代码仍是工作区候选改动。已有网页进程不会自动重新加载 Python 模块；原数据索引也不会因为代码改变而自动更新。具体检查和比较结果记录在下文。

## 3. 候选实现的约束

### 句界切分

复用已安装的 pySBD，将空白字符等长替换为空格供断句，所有返回位置仍对应原文。短句尽量在 token 预算内完整装入；重叠尽量从句首开始；单句超过预算时才允许 Unicode 安全的 token 回退。原文保留区间分别处理，不能用跨间隙上下文填补缺失正文。

`chunk_body` 和 `chunk_retrieval_body` 同时提供 `strategy="sentence"`；默认 `strategy="legacy"`。保持最大 token 数与 overlap 为明确参数，避免只修改一个函数默认值却被外层覆盖。pySBD 是算法预测，不能称为人工保证的完整句界。

### 引用输入去重

同一记录、原文版本、数据集和一致来源信息下，对相邻或重叠原文范围建立临时连续视图，再构造短引用目录。每条输出引用仍必须完整落在一个原始 Evidence 内，保留其原 evidence ID。若跨块短句无法落在任何一个原块中，就按可定位子区间拆分；不以临时合并块绕过数据库校验。

不得跨正文间隙、跨文章或跨版本合并；重叠文字冲突、字符范围与文字长度不符必须阻断。去重只减少重复输入，不保证模型会正确理解说话人，也不能补回未检索到的上下文。

### 为什么不能直接“改完再导入”

当前 `import_batch` 用源 payload 定义原文版本，相同版本会跳过导入；chunker 配置不参与版本。因此只改切法再导入不会替换现有块。绕过跳过逻辑直接追加会混入两种切法，而当前数据版本仍不变化；删除旧块会破坏历史答案的引用。

正式采纳前，需要为索引增加独立的配置和发布版本：从冻结源版本派生新索引、完成向量覆盖与检查、原子切换活动索引、保留历史引用依赖的旧块，并支持回退。不能通过篡改原文哈希冒充正文发生变化。

迁移和评价契约的代码核对见[迁移审查](rag_chunking_migration_review_20260916.md)。

## 4. 检索比较方法

比较 `legacy300/100`、`legacy400/100`、`legacy600/100`、`sentence600/100`，单位为 `cl100k_base` tokens。正文、保留区间、问题和筛选固定。

runner 在 `REPEATABLE READ READ ONLY` 事务中读取当前库，在内存派生片段，通过只读 SQL CTE 复用 English FTS 排序。输出区分每篇最多 1 块的免费搜索预算，以及每篇最多 3 块的付费问答候选预算；后一种仍然是**纯关键词比较**，不冒充实际混合检索。

评价同时保留文章 Hit@5、完整支持原句覆盖、输入 token 数和原文区间重复率。Gold 只用于评分；不将答案记录 ID 偷加到查询过滤条件。中文配对题属于诊断翻译，不是新增的独立金标准。旧开发题、PDF smoke 和中文诊断分别报告。

本轮仅核对已有 embedding 缓存的覆盖率。候选块缺少向量时，不能用旧块向量代替，也不能拿不完整的 hybrid 结果比较方案优劣。生成质量、中文混合检索表现和人工验收仍需后续评价。

## 5. 验证结果与采纳决定

### 工程检查

- 全套 **318 passed**：296 项离线检查＋22 项专用测试库集成检查；[pytest 原始输出](rag_chunking_pytest_20260916.txt)。数据库集成用例只使用 `obs_test` 专用库，未清理主库。
- [Ruff 检查](rag_chunking_ruff_20260916.txt)与 `git diff --check` 通过。未新增第三方依赖。
- 226 篇正文的句界候选共 **556 块**，原文定位、token 重算/上限、非空白覆盖、区间隔离及前进检查零失败；[全库候选检查](sentence_candidate_corpus_check_20260916.json)。该结果只证明这些工程约束。
- 对比 runner 的 `legacy600_baseline.baseline_matches_current_index=true`：同一只读快照下，旧方案的 chunk ID、正文哈希、字符范围、token 数与当前 558 块逐项一致。
- [结果完整性核对](rag_chunking_review_validation_20260916.json)确认两轮报告与当前代码、gold 文件哈希一致，并检查本文及配套审查的本地链接。

完整保留区间的相同 pySBD 口径下，句界效果也已实测：

| 指标 | legacy600 | sentence600 |
|---|---:|---:|
| 句内终点 / 全部块 | 292/558 | 0/556 |
| 句内终点 / 保留区间内非末块 | 292/302 | 0/300 |
| 没有被任一单块完整包含的预测句跨度 | 4/8,192 | 0/8,192 |

因此本批正文上的**句界对齐和单块上下文覆盖确实改善**。8,192 是完整保留区间上的算法预测跨度，不是新人工句子金标准；正文缺失和说话人跨句关系仍没有由此解决。

### 检索结果

两轮结果分别保存于[每篇最多 1 块](retrieval_chunks_lexical_1_20260916.json)和[每篇最多 3 块](retrieval_chunks_lexical_3_20260916.json)。两轮均为纯关键词检索。下表的支持句分母是 8 道 ready 检索题对应的 **13 条 gold 引文**；不把另外的计数题、无证据题和待接社交题放入分母。

| 切法（max / overlap） | 全库块数 | 文章 Hit@5（两轮相同） | 支持句覆盖，1 块/篇 | 支持句覆盖，3 块/篇 | 3 块/篇返回 token 合计 | 3 块/篇原字符重复率 |
|---|---:|---:|---:|---:|---:|---:|
| legacy 300 / 100 | 1,178 | 7/8 | 8/13 | 9/13 | 20,877 | 18.79% |
| legacy 400 / 100 | 816 | 7/8 | 8/13 | 9/13 | 24,122 | 14.91% |
| legacy 600 / 100（现有基线） | 558 | 7/8 | 9/13 | 11/13 | 27,763 | 9.67% |
| sentence 600 / 100（候选） | 556 | 7/8 | 9/13 | 11/13 | 27,017 | 7.73% |

**本批题上，句界方案没有提高文章命中或支持句覆盖。** 其返回块 token 数下降约 2.7%，重复比例减少约 1.94 个百分点。300/400 的块更小，但支持句覆盖更低、重复比例更高，不能因“更细”就默认更好。固定 overlap=100 占小块更大比例，因此这些结果也不能证明所有 300/400 配置都差。

另有两道 PDF smoke：每篇 3 块时四种方案支持句覆盖都为 2/2；每篇 1 块时 legacy300 为 1/2，其余为 2/2。题目本来就用 record ID 锁定了一篇文章，不能作为广域文章召回证据。开发题也大量使用元数据过滤，文章命中容易达到上限。这里的 7/8 是纯关键词结果，与旧报告付费混合检索的 8/8 不是同一实验。

### 引用去重：固定检索结果，单独比较

取上面每篇 3 块的**同一份检索结果**，分别运行 HEAD 中的旧引用目录和新的合并引用目录，没有生成回答。开发题上的 legacy600 结果为：

| 指标 | 旧目录 | 新目录 |
|---|---:|---:|
| 引用候选总数 | 491 | 440 |
| 引用文字 token 合计 | 28,216 | 25,555 |

引用文字减少 **9.43%**，每条新引文仍完整包含于一个原始 Evidence。该计量不含系统提示、元数据、输出 schema，也不是实际 API token 账单或成本下降比例。超长句的 60 词窗口仍有有意重叠，不能宣称所有重复都已消除。

在 sentence600 返回结果上，旧/新目录的引用文字为 27,536 / 25,429 tokens。先对旧索引去重已经拿到了本批题上大部分输入量收益；没有必要为了这一项收益立即迁移全库。[逐题及分组结果](quote_catalog_comparison_20260916.json)保留了原始检索报告和旧/新代码哈希。该结果没有评价模型能否正确归因、理解限定语或使用引文。

### 中文配对诊断

将原来的 7 道英文题各配一条中文翻译，并为原来的中文 dev-08 配英文翻译；重新按问题语言分成各 8 题。保留原 filters 和 gold，不把翻译当成独立标注。legacy600 与 sentence600 的结果相同：

| 语言 | Hit@5 | 支持句覆盖，1 块/篇 | 支持句覆盖，3 块/篇 |
|---|---:|---:|---:|
| 英文 8 题 | 8/8 | 11/13 | 13/13 |
| 中文 8 题 | 5/8 | 6/13 | 7/13 |

中文组三个文章未命中案例是 dev-03、dev-05 的中文配对和原 dev-08。中文并非一律零命中，问题中保留的英文机构名称与显式过滤仍可能命中；但这组配对确实显示 English FTS 的语言限制。没有调用翻译服务、重写线上 query 或测实际向量通道，不能用这组数字断言付费 RAG 的中文效果。

### 采纳决定

**句界切分保留为候选，当前索引继续使用旧 558 块。** 理由是本批 gold 覆盖没有提升，句界方案只有 119/556 块命中现有向量缓存，完整混合检索和回答语义尚未测。其余 437 块不能借用旧向量；当前 legacy600 的缓存覆盖为 558/558。

引用去重的工程实现已完成，真实模型语义回归尚未运行。本轮没有重启网页、重导主库、调用付费 API或执行索引发布迁移；正文版本、历史引用和费用控制保留。后续启用前应检查固定问题的真实回答与人工审查项；需要采用句界方案时，再实现独立索引版本与回退。

## 6. 后续优先级

1. 根据只读比较检查句界对齐、覆盖和上下文开销，决定是否值得进入完整向量比较。
2. 有完整向量及独立审查证据后，再进行索引版本化和发布；保留旧索引与历史引用。
3. 元数据前缀作为单独实验：明确 `title / sponsor / publisher + body` 的输入模板、空值策略和缓存版本，正文位置仍只指原文。结构化 sponsor / publisher 过滤应继续直接走数据库。
4. 对中文、含糊提问和跨广告比较建立真实用户问题集；必要时比较翻译查询与双语查询，保留原问题并记录改写，不能靠提高向量权重掩盖实体识别错误。
5. 当前 558 块不构成必须上 HNSW 的规模理由。外部重排、多 agent 路由和换数据库均延后，直到有明确错误类型或性能瓶颈支持它们。

需要人工解决的项目问题集中在：赞助方字段含义、原文完整性争议、真实用户问题、回答表达主体与引用是否支持转述。切分和检索参数无法替代这些判断。
