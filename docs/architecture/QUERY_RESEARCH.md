# 问答流程与证据边界

所有问答使用统一的阅读顺序：直接答案、支持依据、范围说明。这是全局呈现规则，适用于数量与比例、媒体与赞助方列表、图关系、CLAIMS、记录正文与来源，以及内容问答，不依赖某一种问题或公司名称。广告数量、公司与媒体列表仍由数据库计算。CLAIMS 分类结果仍是独立的数据来源，网页问答不会自动重新分类或发布标签。

## 1. 页面回答结构

1. **Summary**：先回答问题。内容问答的总结关联原文证据编号；数据工具的总结由已返回的统计或记录生成，无需为格式增加模型调用。
2. **Evidence**：内容问答以中性的 **Findings** 分组，并展示可定位的广告引文；统计展示完整类别与对应记录；图关系展示关系类型与原始记录；CLAIMS 展示已发布分类及其证据；正文和来源读取展示指定文本区间或来源链接。
3. **Scope and limits**：明确统计单位、当前筛选、分页与检索覆盖、缺失日期或推断日期、自动分类状态，以及广告主张与外部事实的区别。
4. **Additional web sources**：只有库内证据存在缺口时才可能出现。外部摘要和网页引用使用相同阅读顺序，但独立于库内原文与统计。

澄清、未命中、限额和故障使用 **Status → Next step**，说明缺少什么、应如何继续，不生成没有依据的事实总结。免费关键词搜索呈现命中概况、检索片段和范围，片段数量不冒充广告总数。

例如比较 ExxonMobil 和 Shell：系统应分别检索两家公司谈减排的广告，再总结各自强调的内容。它描述广告中的主张，不据此确定技术实际减排效果。引用编号有效只证明引用连接成立，语义支持仍需要独立评审。

旧回答记录没有新结构字段时仍保留原有正文和引文，不自动压缩出未经核验的总结。服务器提供的日期警告保留在范围说明中。

## 2. 数据与工具流程

```text
问题 + 当前筛选
  → 模型选择受约束的数据工具
  → 统计问题：数据库计算 → 数量、分布和来源记录
  → 内容问题：关键词 + 向量检索
      → 比较问题按公司/媒体分别检索，最多三个目标
      → 生成引用约束的总结与分组陈述
      → 校验原文版本、字符位置、引文及总结的引用编号
      → 库内不能回答时：联网补充 → 单独显示外部来源
```

工具请求只能收窄当前范围。比较目标通过 `search_records.comparison_scopes` 传入，每个目标必须有明确的来源赞助方或媒体，不能用重复目标凑成比较。页面呈现每个目标的检索覆盖情况；找到片段不等于已经证明语义支持，更不等于读完该公司全部广告。

## 3. 联网补查

环境变量 `OBS_WEB_SEARCH_ENABLED=true` 启用，设为 `false` 关闭。`Settings.from_env()` 默认开启；直接构造测试设置默认关闭，避免旧测试意外访问网络。

网页先尝试库内回答。当前服务会对不能完成的回答补查外部来源，包括证据不足、澄清请求或库内服务不可用；请求限额、无效问题、关闭联网或不允许显示来源链接时不补查。补查仍受项目费用预算约束，失败时显示原因和下一步，不能编造回答。

成功补查使用 `answer_mode=web_supplement`。页面明确标注 **Outside the advertising collection**，先呈现带 `[Wn]` 的摘要，再展示网页来源和范围说明。如果原回答已经有可验证的部分广告证据，也保留这部分内容。外部材料可以是广告、公司公告或其他带来源的材料；不自动认定它属于现有广告收藏。

外部页面不进入广告表、向量索引或知识图谱，也不补齐本地记录的日期、赞助方或 CLAIMS 标签。当前筛选作为检索上下文传给模型，但页面不宣称外部结果已经满足全部筛选条件或属于现有收藏。

联网适配器每次使用现有 Responses API 的一次 `web_search` 工具调用。只保留带有效 URL 引用的段落，并提供可点击的 `[W1]` 等引用。未带引用的生成段落被丢弃。外部内容是模型转述；程序没有下载网页验证全文，因此它没有本地引文的字符定位保证，也没有事实核查保证。页面明确区分两类来源。

API 费用使用原有预算预留与结算。联网有额外费用；未知请求结果仍保留费用预留，不盲目重试。当前价格配置只支持既有配置模型。没有为这次改动调用真实付费模型。

实现依据：[官方 Web search 文档](https://developers.openai.com/api/docs/guides/tools-web-search)、[官方 Function calling 文档](https://developers.openai.com/api/docs/guides/function-calling)。

## 4. MCP 接口

网页继续使用 Responses function calling；独立 MCP 服务使用同一受限工具目录。两个传输共享工具逻辑。

启用联网后，独立 MCP 额外提供 `search_external_sources`：

1. 先调用 `search_records`。
2. 无关键词片段、无被拒绝证据且数据健康时，返回五分钟有效的 `web_fallback_ticket`。
3. 用该票据调用联网工具；票据一次性使用，不允许提供任意新问题、URL 或 SQL。

MCP 票据证明的是一次空的关键词检索，不证明整个数据库没有语义相关内容。网页会先做混合检索和引用约束生成，再决定补查。MCP 联网工具会写费用账本，其注解为有费用、非幂等、开放外部来源；不是纯数据库读取。

原有 `find_claims_source_candidates` 属于 CLAIMS 来源维护，不作为公共问答补查工具。

## 5. 加载状态

页面显示加载圈与正在执行的阶段：问题解读、广告数据库检索、联网搜索、整理有来源的回答、核对引用。阶段由实际操作报告，不按计时器编造进展，也不展示模型私有推理。

状态按用户会话与页面标识隔离，最多保留 512 项、15 分钟到期。完成或失败时停止轮询、恢复按钮。当前状态存储适用于单进程 Waitress；部署为多个进程时应先改成共享状态存储。

## 6. 验证和待办

离线测试检查：分别检索、筛选约束、空证据补查、统计与错误不联网、MCP 票据、外部引用与费用、总结编号与语言、加载状态隔离和完成清理。测试使用独立合成夹具，不修改现有冻结问题集。

待验证：

- 原始客户比较问题的真实模型回答质量；
- 外部结果是否确为相关原生广告，以及总结是否被引用支持；
- 独立的人审与客户验收；
- 多进程状态存储，以及社交数据接入后的独立验收。

工程测试通过不代表上述语义质量已经通过。付费验证与推送部署按项目协作协议另行批准。
