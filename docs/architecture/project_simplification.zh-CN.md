# 项目简化审核

2026-10-08。来源：用户要求重新核对项目文件与流程图、减少冗余并作一般改进。归属 user goal；客户基准、原件及验收要求不变。

## 结论

目前最明显的冗余是**多份文档各自维护同一流程和状态，逐渐互相冲突**。数据库、工具、RAG、离线分类和评价各有不同职责，不适合合成一个“大模型步骤”。

当前主流程以[架构及流程图](architecture.md)为准。简单理解：先保存可追溯的原始资料；统计查SQL；内容问题检索后生成；CLAIMS离线分类；独立评价只检验结果。

## 保留的必要结构

- **统计与检索分开**：全库数量不能从前几个检索片段推算。
- **来源版本与引用检查**：更新正文后，旧引文不能冒充新正文证据。
- **原文与派生素材分开**：图片描述、字幕、转写不能写成文章原句。
- **离线CLAIMS与在线RAG分开**：分类结果可以复用，日常问答不重复分类。
- **开发与客户评价分开**：保持客户题掩码；工程检查、语义审核和客户验收各自记录。
- **客户端来源与用户选择分开**：不能把我们的实现选择改写成客户要求。
