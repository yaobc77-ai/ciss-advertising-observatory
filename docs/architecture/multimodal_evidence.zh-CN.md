# 文字、图片和视频：分开准备与检索，最后合并证据

更新：2026-10-06。**本机离线模块和人工素材队列已实现；实际图像识别、字幕获取、视频转写及主网页检索接入未完成。**

## 先用人话说

同一篇广告里的正文、图片和视频要分别处理。文字引用能回到一句话；图片证据能回到一张截图和区域；视频证据能回到某个时间段。查询时三路各自找候选，最后汇集到同一篇广告下，保留每条证据的种类和位置，不能把三段素材算成三篇广告。

视频先用已有字幕。确认没有字幕、但有人声，才计划一次省力转写。确认无人声时，进入人工素材区，请人提供截图、时间或画面描述；高级模型可以负责后续图像识别，但先明确模型、预算和授权。**有音轨不等于有人声，页面静音也不等于文件没有音轨。**

人工描述只是“人提供的画面描述”。没有截图或时间时，它是未定位备注；有截图也要核对其来源。保存备注、图片哈希或描述，不等于已经识别图像、恢复字幕或准许入库。

本轮依据是用户在本机审核页面的补充意见：图片、视频单独切分，分开检索再合并；无声素材转人工补截图或描述。用户原话“无人生则进入人工标注区”暂按“无人声”理解，原话与解释分开保留。该实现属于用户技术要求，不自动改写客户原要求。

## 本轮已经能做什么

| 内容 | 已实现 | 尚未执行 |
| --- | --- | --- |
| 正文 | 复用已有句界切分；原字符位置、版本、哈希和既有检索区间不变 | 没有重建生产数据库或向量 |
| 图片 | 接收明确标注为OCR、模型描述或人工描述的派生文字；绑定截图哈希、页码和区域，单独形成候选 | 没有运行OCR或视觉模型；区域语义尚未审核 |
| 视频 | 接收已带时间的字幕／转写片段，标明来源与质量；单独切分与召回 | 没有获取字幕、下载媒体或执行转写 |
| 融合 | 三路词项候选先各自排序，再按记录和版本合并；保留种类、时间、区域及原字符位置 | 没有把新类型送进生产RAG生成器 |
| 人工材料 | 生成26条具体记录的队列；校验描述／截图请求并保持待审，记录高级图像识别意向 | 不自动变成证据、字幕、主应用准入或付费运行 |

本轮的检索是**离线词项基线**，用于核对分流、范围和证据契约。现有网页的PostgreSQL／pgvector检索没有修改。离线候选命中不代表新的语义准确率。

## 技术入口与契约

实现：[media_evidence.py](../../src/observatory/media_evidence.py)。准备命令：[prepare_media_evidence.py](../../scripts/prepare_media_evidence.py)。检查：[test_media_evidence.py](../../tests/test_media_evidence.py)。复用已安装的Pydantic及已有句界切分，没有新增模型或框架依赖。

每条素材先绑定`asset_id / record_id / version_id / sha256 / media_type`。派生文字有自己的`TextArtifact`、来源类型、产生者和哈希；它的字符位置属于这份派生文字。

| 证据类型 | 原素材定位 | 可以怎么说 | 不能怎么说 |
| --- | --- | --- | --- |
| 正文 | `CharacterLocation`：原正文字符起止和body哈希 | “这句存在于保存正文” | 不因存在引文就说主张真实 |
| 图片 | `ImageLocation`：截图哈希、页码、归一化区域；视频截图可另带父视频和帧时间 | “OCR读到的文字”“模型／人工对画面的描述” | 不把OCR字符位置沿用到原文章，也不把描述当图片原文引语 |
| 视频 | `TimeLocation`：已提供片段的起止毫秒；字幕／转写文本另有派生位置 | “发布者字幕”“自动字幕／转写，未逐字核对” | 不从人工描述制造字幕，不把片段时间说成精确逐词时间 |

`retrieve_separately()`必须接收可信的当前记录版本范围。待准入、撤回或旧版本素材不返回；`merge_candidates()`再次核对同一范围及已验证的bundle，防止手动塞入过期候选。融合用各类型在该记录上的最好排名做RRF，同一路重复片段不会增加广告数或重复计分。

`citation_payload()`也必须检查可信的当前记录版本范围，只从验证后的bundle取证据，按类型输出位置及质量说明。图片描述和视频转写均不会标成原正文引语。字节、区间和哈希检查只能证明定位与版本一致，**不能自动证明图片区域包含这些含义，也不能证明字幕忠实于语音**。

模型对象设为只读，也不能保证里面的列表不变。独立复核曾在内存中追加与原正文不符的片段，复现了错误的引用放行；现已在检索、融合、引用、本机哈希检查与人工材料登记入口重新验证整个契约。对应回归会拒绝这类片段，不改原保存资料。

准备器还复用已有完整正文准备工具的身份检查：正文必须与payload一致，payload哈希必须对应记录版本，记录ID、数据集、准入标志及检索区间必须一致。独立复核构造的“更换顶层正文但沿用旧版本”会在写新材料前被拒绝，避免把新文字包装成旧版本证据。

### 人工入口

人工入口先保存如下材料，保持`pending_source_and_location_review`：

```json
{
  "task_id": "media-task-...",
  "record_id": "原记录ID",
  "version_id": "对应记录版本的64位哈希",
  "asset_id": null,
  "reviewer": "可选姓名",
  "description": "我在画面中看到了什么",
  "description_kind": "visual_description",
  "screenshot_refs": [],
  "time_start_ms": null,
  "time_end_ms": null,
  "request_advanced_vision": false
}
```

图片经本机入口保存后，可以添加截图引用，包含文件哈希、页码或帧时间。`region: [0,0,1,1]`表示提供的整张截图，并非模型已定位到具体物体。未提供定位时只保留未定位备注，不强行造位置。高级模型选项只表达意向，状态保持“待明确模型、预算和授权”，该模块没有模型执行器。

## 本地运行

在项目目录执行，使用已有环境：

```powershell
.venv/Scripts/python.exe -X utf8 scripts/prepare_media_evidence.py prepare
.venv/Scripts/python.exe -X utf8 scripts/prepare_media_evidence.py demo
.venv/Scripts/python.exe -X utf8 -m pytest tests/test_media_evidence.py -q
```

`prepare`读取冻结文件并写新的私有材料。输出已存在且内容不同时拒绝覆盖；重做请用`--out`指定新目录。`demo`只有合成正文、1像素图片和明确标记的时间元数据fixture；文字描述及字幕也是合成回放，**不是对真实图片或视频运行模型**。

可另用`check-material --submission ... --out ...`校验人工材料字段与保存版本，输出仍是待审核材料。程序不会依据这个命令更改业务数据库或发起推理。

## 后续要满足的条件

1. 先核对具体图片、截图或视频是否属于选中广告，取得可访问素材和必要定位；原稿、派生文字、语音与画面分别保留。
2. 对有字幕的视频复用字幕；无字幕且确认有人声才按现有省力方案小批转写。无人声时收截图／描述，再确定是否需要视觉模型。
3. 高级视觉模型单独冻结输入图像、提供商、模型、次数、费用与停止线；普通文章和图片不自动继承视频转写的准确性让步。
4. 分别评价文字、图片、语音的检索及引用，检查语义遗漏和错误；不同来源矛盾时保留分歧，不让融合步骤“自动达成一致”。
5. 主网页／MCP必须增加按类型读取和引用的适配，并检查记录版本、当前筛选与来源资格，再讨论真实接入。当前工程模块完成，不等于这几步已经交付或客户验收。
