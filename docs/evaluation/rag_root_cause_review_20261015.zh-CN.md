# RAG 准确率独立复盘：范围、覆盖、判定与评估

日期：2026-10-15。性质：独立诊断和改造建议；不是新的付费评测、生产修复或客户验收结论。

## 1. 结论

F26 检索上限和 F27 实体类型修复有实际价值，R 轮确实比 Q 轮找到了更多相关广告。但当前主要矛盾已经从“多取一些检索结果”，转向四个贯穿全流程的问题：

1. **问题中的范围和交付要求没有成为所有工具共同遵守的执行合同。** 防止模型添加不存在的筛选，并不等于防止模型漏掉明确要求的筛选；执行一次内容搜索还可能覆盖原有组合任务。
2. **排序检索被用于要求完整集合的任务。** 前 120 篇、连续 16 篇无匹配就停，只能构成有界搜索；不能证明剩余记录均不符合。
3. **候选记录、已读原文、语义判断三个层次缺少独立的完整性记录。** 扩大记录数仍可能漏读尾部；小范围“整体读取”实际上仍是每篇至多 3 个检索片段和总长度截断。
4. **参考答案随运行变化，评分器存在缺口，筛查输出也不稳定。** 当前分数是特定自动判分规则的通过率；不足以解释为“完整名单准确率”或“只剩 5 篇系统错误”。

建议做一次主流程整合：以现有类型化意图结构为基础，形成“任务合同 → 范围解析 → 记录集合 → 阅读与判断 → 集合运算／汇总 → 完成度核验”的统一路径。详细方案见[决策树与改造计划](rag_decision_tree_proposal_20261015.zh-CN.md)。不建议再优先堆词面规则，或仅把 low 改为 medium。

## 3. 分数到底说明什么

### 3.1 原报告按题型重现无误，但应称“规则通过数”

| 题型 | Q | R | 可支持的结论 |
| --- | ---: | ---: | --- |
| O：内容、统计、标题及无答案等 | 24/35 | 28/35 | 混合题型改善，不能由合计定位具体机制 |
| T0：字段／属性 | 10/10 | 10/10 | 当前机械规则全部通过，仍需加强评分器 |
| T1：主题提及名单 | 19/25 | 25/25 | 全部达到精确率、召回率各 80% 的门槛 |
| T2：框架／定位 | 8/13 | 8/13 | 无题级净改善 |
| T3：态度／立场 | 5/6 | 5/6 | 样本少，无法精确估计一般能力 |
| T4：修辞 | 2/6 | 3/6 | 有改善，仍弱，且参考边界有争议 |
| 合计 | 68/95 | 79/95 | 两轮各自参考下的自动规则通过数 |

O 内部：单篇内容 9→10/13，多篇内容 0→0/2，时段内容 2→3/3，跨集合 2→2/3，统计 3→5/6，标题 3→3/3，无答案 5→5/5。全库框架题仍为 0/3。2 道或 3 道只能作为失败线索，不能当作稳定总体准确率。

### 3.2 “同一套题”不等于“同一参考答案”

`score_b1k.py` 会根据本轮引用及漏掉的记录调用／复用 adjudication，再增删本轮正例集合。两轮有 **20 道题的有效正例集合不同**：Q 相比原始参考新增 42、删除 3 个问题—广告对；R 新增 66、删除 3 个。太阳能题的 76→81 正例变化就是一个例子。

离线敏感性分析如下；后两行都**不是新的真实准确率**：

| 比较口径 | Q | R | 用途与限制 |
| --- | ---: | ---: | --- |
| 原报告：每轮各自调整参考 | 68/95 | 79/95 | 保存历史结果，但比较同时受参考变化影响 |
| 名单题统一使用出题时冻结参考，其他题沿用现存判分 | 59/95 | 66/95 | 控制名单参考一致；原参考已知不完备，不能把新增正确来源全部判成真错误 |
| 名单题统一合并现存两轮复核结果，其他题沿用现存判分 | 60/95 | 78/95 | 事后共同参考的诊断；仍依赖系统发现哪些候选、已有 AI 判断和未审记录，不能当作独立金标准 |

三个口径都显示总通过数改善，但增幅明显依赖参考处理。能说“修复有效”，不能据此给出无条件的准确率增幅。

### 3.3 “名单题全对”的标准过宽

名单题规则为 `precision >= 0.8 and recall >= 0.8`。以各自发布参考计算：

| 指标（50 道名单题） | Q | R |
| --- | ---: | ---: |
| 达到门槛 | 34/50 | 41/50 |
| 返回集合与参考集合一致（按评分器排除 neutral） | 28/50 | 33/50 |
| 纳入评分的引用问题—广告对（排除 neutral） | 277 | 361 |
| 真阳性／假阳性／漏项 | 273 / 4 / 91 | 356 / 5 / 32 |
| 微平均精确率／召回率 | 98.56% / 75.00% | 98.61% / 91.75% |

R 的 T1 是 **25/25 达到门槛，21/25 集合完全一致**。R 全部名单题有 8 道通过门槛但集合不完全正确。上述集合指标沿用评分器排除 neutral 的规则；T1 没有 neutral。这里的“真／假”均相对于当前 AI 辅助参考，并非人工确认的客观真值。两轮微平均分母也受参考变化影响。

评分器还存在独立缺口：离线构造的服务失败空答可通过 no-answer 规则；答案中出现正确数字但明确说“未知”可通过部分统计规则；否定正确字段的句子可通过标题字段词匹配；只写通用披露词也可通过某些 T0 规则。这些是评分器反例，不表示所有实际已通过答案都错。新评分应验证结构化值、范围、状态和支撑关系。

## 4. 根因与证据强度

### A. 范围约束只在部分路径执行

**已证实的执行缺口。** 统计路径有问题—请求范围守卫，普通 `search_records` 更侧重禁止凭空添加名称，没有等价地检查明确实体或日期是否遗漏。Q009 的日期保留、赞助方遗漏因此可能合法执行；扩大读取上限无法找回一个已丢失的范围条件。

独立虚构输入“Larkspur Energy 在 2021 年的原生广告说了什么”在脚本化规划器只传 `dataset=native` 时，仍进入 evidence 路径；现有 `literal_scope_preserved` 单独调用却会拒绝同一输入。说明已有保护未贯通所有执行入口，不能只靠给模型增加提醒。

**改法：** 在服务端形成有来源的范围合同，覆盖 dataset、实体角色、日期、标题、并集／交集。每个检索、统计、阅读调用都验证“允许范围内”及“明确必要条件没有遗漏”；未知名称或实体角色歧义先解析，不能静默降为全库。不要把内容关键词当作采集关键词字段。

### B. 互斥路由破坏组合问题

**已证实的控制流问题。** `research_agent.py` 中内容搜索可将已有计划替换，清空任务和已完成列表。虚构“解释一个广告的内容；统计该赞助方广告总数”的两任务计划，执行搜索后不再保留独立计数任务。现有类型化意图默认关闭，也不完整支持 evidence 与其他任务组合、完整名单和内容筛选后计数；适配器还会丢弃已编译的 `answer_shape`。

**改法：** 用可组合的任务依赖关系取代单一终止路由。把“筛选哪些记录”“交付举例还是完整名单”“按什么分组”“要不要计数／比较／解释”拆成独立维度。A 或 B 的并集不自动等于比较；内容条件加计数应先筛选记录集合，再聚合，而不是在 SQL 与内容问答之间二选一。

固定四步还把规划、实体定位、修复和实际读取放在同一预算内，某些合法组合先天不可完成。实体工具已发现跨类型同名来源时，最后一步仍可能被解释为“库里不存在”。应保留真实的“解析／执行预算耗尽”和剩余任务，而不是改写成来源缺失。相关位置：`research_agent.py:534`、`:972`、`:1088`；这是静态可达问题，未估计在 R 中的发生比例。

### C. 完整名单没有完整候选集合

**源码确定的能力上限；当前运行已观察到漏项。** `db.py:1142` 将通道上限提高到 `max(50, 2 * limit)`，修复了旧的 50 段瓶颈。但这是片段数，不保证不同广告数。普通名单仍受 120 候选和“前 40 后连续 16 个无匹配就停止”控制；字面短语检索可补候选，不能作为一般语义条件的穷举保证。

按 R 各自参考，漏项为 **5 未检索 + 6 检索但未读 + 20 已读判不符 + 1 已读不确定 = 32**。之前的 31 漏掉了 unclear；“20 篇”与“21 篇”不是同一个判定集合。统计单位是问题—广告对，同一广告可出现在多道题中。

**改法：** 完整名单首先在固定数据版本上枚举过滤后的记录 ID 集合，再调度阅读。相关性只决定先读谁；达到预算时返回部分结果和剩余数量。仅在枚举完整、每条记录满足规定的阅读／决策条件时允许标记完成。语义筛选器仍可能误判，这种完整性不等于语义正确率 100%。

### D. “整体读取”与实际原文覆盖不一致

**源码与实际载荷均证实。** F28 的 `_small_scope_size` 只是提高 `db.search(limit=...)`：`service.py:1559` 附近仍为普通内容题设置每篇最多 3 段，随后套用 30,000 字符总预算。并没有逐 ID 读取全部正文。比较路径每组只取 3 条候选，再合并压缩，也可能缺少某组必要证据。

名单路径 `_merge_article_passages` 调用 `db.record_passages(per_record=8)`，合并“前 8 段 + 已检索片段”。它也不是全文完整读取。冻结 native 快照有 8 篇文章超过 8 段；实际 Q056 请求漏掉某篇第 10–11 段。不过其争议正例句位于已发送的第 9 段，**该具体误判不能归因于这两段缺失**。

实际 50 道完整名单题中，有 **59 个已筛查问题—广告对缺少至少一个已存索引段落**；其中 29 个判不符、30 个判符合、0 个判 unknown。缺段不证明这 59 个结论都错，29 个负判也不等于确认了 29 个语义错误；但系统没有在这些结果中显式保留完整阅读的不确定性。更上游还有资格分母：快照 275 条中，263 条可计数、232 条可检索，31 条可计数记录没有 chunks。名单参考并未覆盖这些不可读内容，不能把它们视作已判负例。

**改法：** 记录每条来源的总片段／原文范围、已读范围、缺失范围、来源可用性。无完整可读文本时，未找到证据应为 unknown，不能被折叠成全文不符合。长文按 token 预算分块判断，再进行文章级合并；否定、引述和反证需要上下文，不允许只找到关键词就完成。

### E. 语义判定缺少可审核的条件分解，批次也不稳定

**已证实的表示不足，效果归因尚需控制实验。** T1–T4 共用一个逐篇判断提示，主要输出 matches／does_not_match／unclear 和单句引用。它未显式表达“谁主张、主张什么、力度多强、是否否定、是否仅引用他人、是愿景还是已实现”。负例通常也不保留足够的理由／覆盖证据。引文存在验证有用，但不能证明引文支持题意。

两轮共同筛查的 **1,210 个问题—广告对**：57 个在“匹配／不匹配或不确定”之间翻转；按三态计算是 83 个，其中另有 26 个在不符与不确定之间变化。83 个中 82 个广告自身文本相同，但只有 **5 个翻转对分布在 3 组日志中 SDK 调用参数完全相同的批次请求内**，其余批内文章、位置或文本变了。这 5 个原始模型输出均从不符变为符合，支持“相同记录请求下观察到了输出变化”；不能把所有 57 个归因于相同输入下的随机性，更不能据此预测升推理档位的收益。Q020／Q083 的完整批次均发生变化。

请求相同的哈希检查包括完整 system／user 输入、所有文章及次序、模型、schema、输出上限、reasoning 和 store 等显式 SDK 参数；不控制模型别名背后的版本、HTTP 头或未记录的后端状态，故不将波动归因到特定随机机制。

固定 8 篇一批也不是固定文本预算：R 最大一批约 141,412 个正文字符、31,905 输入 token。上下文量、邻居和位置影响是合理假设，尚非因果结论。

**改法：** 先冻结通用判定定义，输出结构化支撑、反证、角色、模态及 unknown 原因；批次按 token 控制且使用稳定记录标识。对缺失文本先补读，对明确语义分歧才考虑复判。缓存必须以来源版本、问题谓词、rubric、模型／提示配置为键；缓存只是复现控制，不是正确性证明。

### F. 只修 21 个争议参考会带来选择偏差

**评估设计问题。** 21 个漏项样本上的“5 严格／7 两可／9 参考错误”是一次有价值的定性复核，但样本是按系统错误选出来的，且未完成盲审或一致性测量。不能推广为“系统真正只错 5 个”，也不能知道系统通过题中是否有同类参考偏差、漏召回或误列。

**改法：** 保留旧参考和旧成绩，先制定来源独立的通用定义，再盲审正例、负例、双方分歧和未检索区域，形成新版本。两可项保留 unknown／disputed，公开数量与覆盖率；可以另报剔除争议项后的结果，但必须同时保留完整分母和原结果。统一新参考后同时重评 Q 和 R。最终效果在新的来源／时间分层留出集验证。

## 6. 建议顺序

1. **先修测量与合同：** 冻结参考及评分版本；统计和字段改用结构化判分；统一范围核验，保留所有子任务。
2. **再改集合与阅读：** 增加可分页的固定版本记录集合，完整列表与内容计数共用集合筛选；增加正文覆盖账本和明确的 partial 状态。
3. **再改语义：** 通用谓词定义、证据／反证结构、长文阅读和按 token 批处理，单项消融验证。
4. **最后考虑预计算和模型升级：** 对固定且可审核的常用属性做版本化离线证据索引；自由问题仍查询时判断。既有 CLAIMS 审核标注与新查询时 AI 暂定判断保持区分。

每阶段验收条件、迁移方式及决策树见[下一份方案](rag_decision_tree_proposal_20261015.zh-CN.md)。本轮完成的是诊断与设计，不宣称上述修改已实现，也不承诺未经测试的目标准确率。
