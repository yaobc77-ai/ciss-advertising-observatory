## 怎样避免把测试答案当训练数据

1. 24题原始文件按字节复制并保存SHA256；客户原题与旧18变体不进入新训练候选。
2. 新训练内容不读取 `24_answer.md` 或其33处参考例证；不生成围绕蓝氢、CCS等24题的近义内容题。训练问题措辞还检查与原题及旧变体的相似度，出现较高重合即拒绝。这不是完整的语义改写检测，示例启用前仍需审核。
3. 每条候选保留记录ID、版本、正文哈希、来源URL与标题；引用保留原字符位置。确定性数量由冻结字段重新计算并核对所有成员；原候选语义空值不覆盖，教师判断另存并标明未获人审。
4. `runtime_enabled=false`：没有把候选注入网页提示词或示例检索，没有训练任何参数。审核人、批准时间目前为空。
5. 训练候选的来源可以与客户263篇测试范围重叠，清单明确声明这个事实。因此不是文档独立留出。**RAG检索测试题所需的原始广告属于允许的知识库；把测试题、测试答案或人工判定加入拟合参数／提示示例才是需要禁止的答案泄漏。**

补充运行边界：现有研究代理已把Q01–Q24的题目定义作为业务目录传入，用于选择已审内容结果的题目ID。这是已存在、已知的运行配置，不能声称题目对系统隐藏。本轮没有把测试参考答案或新训练候选加入该目录。材料中“不得加入提示词”指不得作为训练或提示示范；正常测试当然需要把当前测试问题提交给系统。客户任务测试评估整个已配置系统，不等于未见问题泛化。

## 什么算准备足够，什么还不够

本轮用以下工程门槛检查材料规模：至少240条候选、至少8类任务各有6条、至少40个来源组、至少160条确定性可复算候选。实际为547条、18类各有6条以上、251个组、427条确定性候选，全部达到准备门槛。

这组门槛是为了避免只测几道例题，没有统计学上的“泛化保证”。确定性参考只是冻结记录字段计算正确，不证明来源字段、计数业务口径或页面完整性已获客户批准。120条已有AI阅读，2条未解决；人工标准答案、客户24题完整参考和社交覆盖仍缺失。

客户24题仍需具名审核：选择审查子集时只报告子集成绩；若声明263篇全库的完整名单召回，需要审定24×263＝6,312个问题—广告判断。只做命中片段检查不能代替完整相关集合。

## 运行和审查入口

```powershell
$env:PYTHONPATH = 'D:\Projects\549 native ads\src'
python -X utf8 scripts/prepare_rag_training.py --out .runtime/rag_training_split_20261006/a-new-output
python -X utf8 -m pytest tests/test_rag_training.py -q
```

准备脚本拒绝任何已经存在的输出目录，包含空目录；原件、旧产物和历史报告不会被覆盖。输入默认是已有冻结快照、客户原24题文件和旧18题的分组产物，不读数据库或联网。

本次选定的本机材料在 `.runtime/rag_training_split_20261006/prepared_v2/`：

- `summary.json`：先看数量、任务覆盖、人审与未见测试的真实状态。
- `training_candidates.jsonl`：每条自然语言任务、确定性参考／待审字段、来源及原句。
- `review.csv`：按任务家族筛选，再填决定、审核人和原因；此表暂未写回批准系统。
- `client_task_test.json`：24个固定测试角色与逐题来源；`inputs/client_questions.original.json`保留原始字节。
- `development_variants.json`：旧18开发题，单独保留。
- `manifest.json`：输入、脚本哈希、冻结时间、文件哈希及使用限制。

首次 `prepared/` 产物也保留，`prepared_v2/`另补脚本冻结哈希和正式未见评价器的使用边界；训练候选与原题没有因此改变。

## 后续如何测

先审核候选及24题参考，再冻结代码、提示词、数据、题目、判定规则、模型和配置，才执行客户任务测试。看到测试结果以后若改提示词或规则，要记录改动；之后再跑属于回归，不能把它称为第一次独立测试。

另收集未参与开发的新任务／文档，独立审定后才能建立未见测试。当前已有教师模型原文阅读，但尚未运行被测系统预测，也没有质量成绩；工程检查不替代客户验收。
