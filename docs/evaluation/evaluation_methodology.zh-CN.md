# 面向用户的评价指标与方法

版本：`customer-metrics-v1`。制定日期：2026-10-05。状态：定义草案已实现，客户验收门槛未确认，正式成绩尚未发布。

网页入口：右上角 **Tools → Evaluation**，地址 `/evaluation`。

## 1. 我们要评价什么

评价对象是用户完成研究任务的结果：能否得到正确统计、完整且相关的关系／广告名单、充分的原文证据，以及清楚的缺失信息说明。范围来自项目的六个研究问题、9/25 会议、Michelle 的反馈邮件和新增的 24 个验证题。

需求依据可追溯到[项目说明逐条整理](../../客户需求/02_逐条整理/PD_项目说明逐条.md)、[会议纪要逐条整理](../../客户需求/02_逐条整理/MT_会议纪要逐条.md)、[客户邮件逐条整理](../../客户需求/02_逐条整理/EM_客户邮件逐条.md)和[新增验证题审查](rag_validation_requirements.md)。本文件提出评价方法，不把它当成客户已经批准的标准。

不把测试数量、检索片段数量、引用字符匹配或模型自报置信度叫作“回答准确率”。也不把不同性质的指标平均成一个总分。

每项结果必须附带：**分子／分母、评价单位、数据集、任务类型、已执行／已审查／待办数量、评价日期、代码／提示词／数据／索引／题集版本、审核记录及适用限制**。网页已支持显式接入冻结运行报告，但目前没有配置真实审查结果，只展示定义和待评状态；没有审定结果时不显示 0% 或 100%。

## 3. 指标定义

“通过”按事先冻结的标准判定，不能看完系统答案再改标准。每项比率的分母为零时结果是“不可计算”，不是满分。

| ID | 指标 | 分子／分母与通过条件 | 判断方式 |
| --- | --- | --- | --- |
| M01 | 研究任务正确率 | 满足全部必需输出和范围限制的任务数 ÷ 有固定参考答案的已执行任务数。遗漏关键部分、越界、服务失败或超时均不通过。 | 独立参考核对；内容任务加原文人审 |
| M02 | 统计与范围一致率 | 所有数字与筛选范围完全正确的统计任务数 ÷ 已执行统计任务数。必须同时核对计数单位、分组、时段端点、全部并列项、分子分母和未知日期；数字碰巧相同不算通过。 | 独立枚举完整记录集合，测试实际提交问题的路径 |
| M03 | 关系名单精确率 | 正确返回的不同关系数 ÷ 返回的不同关系数。关系身份包括数据集、关系类型和两端实体。 | 对照已审定的关系集合 |
| M04 | 关系名单召回率 | 正确返回的不同关系数 ÷ 评价范围内全部应返回关系数。 | 必须完整枚举参考集合 |
| M05 | 图谱点选一致率 | 展示正确对应关系、数量和记录集合的点选次数 ÷ 已执行点选次数。选公司、媒体和边都要测，不只核对总数。 | 在组合筛选和空结果下核对点选输出 |
| M06 | 广告名单精确率 | 满足该题语义条件的返回广告数 ÷ 返回的不同广告数。 | 全文审核；不能把关键词命中当正确答案 |
| M07 | 广告名单召回率 | 正确返回广告数 ÷ 完整审查的评价范围内全部相关广告数。 | 必须有完整成员金标准；只查 Top K 不能证明找全 |
| M08 | 陈述证据支持率 | 有足够引用和原文上下文支持的不同事实陈述数 ÷ 答案中的全部不同事实陈述数。总结、证据转述和带事实断言的标题都纳入；无引文陈述不能被排除。 | 审阅者判断原文是否支持陈述，无依据的新增因果、比较或排他结论不通过 |
| M09 | 归属与限定保留率 | 正确保留主体及相关限定的不同事实陈述数 ÷ 全部不同事实陈述数。逐项检查谁说、文章如何处理、单位、条件、日期、规划／已实现。 | 原文人审；任何会改变含义的遗漏均不通过 |
| M10 | 引用可追溯率 | 通过对应来源类型身份和恢复检查的引用数 ÷ 输出引用数；内部引文、结构化统计、外部网页分别报告。 | 按下面的类型规则核对。能追溯不证明相关、语义支持或事实真实 |
| M11 | 缺失信息处理正确率 | 正确执行预定处理规则的困难任务数 ÷ 所有指定的无证据、歧义、未审分类、未接入资料和工具失败任务数。 | 核对响应状态、说明和范围；联网来源不得混入本地广告数量 |
| M12 | 不必要拒答率，越低越好 | 有足够依据却被错误拒答／判为无证据的任务数 ÷ 有审定参考答案的已执行可回答任务数。 | 与 M11 一起看，防止靠大量拒答提高其他成绩。超时作为运行失败计入 M01，不冒充无证据拒答 |
| M13 | 用户独立完成率 | 在预定时间内无需开发者帮助、得到正确结果并完成来源访问／导出要求的用户任务次数 ÷ 已尝试的用户任务次数。 | 观察实际记者、律师或研究者；同时报告人数、帮助次数和耗时 |
| M14 | 必需回答点覆盖率 | 正确回答且有充分证据的必需点数 ÷ 任务标准中的全部必需点数。比较题必须覆盖每个目标，额外背景不能加分。 | 执行前定义要点，拒答和运行失败的必需点计为未覆盖 |
| M15 | 端到端等待时间 | 从提交操作到结果可用或终止失败的时间；分别给出中位数 P50 和最近秩 P95。 | 按筛选、图谱、统计问答、内容问答分开；包含失败，并记录缓存和冷／热状态 |
| M16 | 每次提交的 API 费用 | 该次运行已结算的模型、问题向量和联网搜索费用总和 ÷ 全部提交任务数。 | 使用账本，包括失败与重试；缺账或未决预留时只报已结算部分，不称最终完整费用 |

名单中的 TP 是正确返回项，FP 是错误返回项，FN 是漏掉的相关项。精确率为 `TP/(TP+FP)`，召回率为 `TP/(TP+FN)`；F1 可在技术明细中辅助展示。此定义沿用信息检索的集合评价，相关性必须相对于具体问题判断。[Stanford 信息检索教材](https://nlp.stanford.edu/IR-book/html/htmledition/evaluation-of-unranked-retrieval-sets-1.html)

M10 的检查按来源类型定义，避免用本地段落规则错误否定联网引用：

- 内部原文引文：广告身份、正文版本、精确引文和字符位置都有效。
- 结构化统计来源：冻结的数据版本、实际筛选、支持记录集合和计算记录能够恢复。
- 外部网页：URL、页面来源身份、检索时间和保存的支持材料可核对；直接引文还须匹配保存材料。单有 URL 不通过，可追溯仍不等于来源可信。外部来源不得被当作集合成员加入统计。

当前已有内部引文定位检查；结构化来源的评价接入及外部引用的完整检查仍待实现，不能以此定义宣称已有实测通过率。分类型分别报分子分母，不用大量内部引用掩盖外部缺口。

### 名单与拒答的边界

- 原子陈述是一个可单独判断支持与否的命题。复合句先拆开；同一答案重复同一事实只记一次，总结新增的范围、因果或比较另计，避免重复正确句子抬高成绩。不同答案分别计分。
- 空返回但有相关广告：召回率为 0，精确率无分母；同时任务不通过，不能把精确率记为 100%。
- 参考名单与返回都为空：精确率／召回率不适用；核对正确无结果处理和任务标准。
- 未完成全文审核：未处理广告是未知，不是阴性；完整名单召回率不发布。
- 每题先按精确广告身份去重。跨题汇总时单位是“问题—广告”对，不能把不同问题中的同一广告合并。
- 同时报每题结果及微平均。宏平均只对定义成立的题求均值，并注明排除题数；无结果和拒答仍留在任务成功率与覆盖率中。

### 24 个验证题的判定规则

| 类型 | 题号 | 需要的参考依据 |
| --- | --- | --- |
| 广告披露措辞 | Q01 | 页面、截图或保留正文中的实际文字与位置；正文缺少标识不能推断页面没有标识 |
| 内容出现 | Q03、Q06、Q15 | 原文中出现概念；引用、质疑或反驳中的出现仍可算提及 |
| 出现及归属 | Q17、Q19 | 能源需求的含义，或慈善活动与赞助方的正确归属 |
| 主张、关系和表达方式 | Q02、Q04–05、Q07–14、Q16、Q18、Q20–24 | 对象、说话者、关系、文章处理方式与限制；共现的关键词不够 |

Q15 遵循客户给出的 `climate_science` 出现规则：“climate change”的单纯出现也足够；符合科学共识和怀疑共识另行编码。广告将 CCS 描述为可行方案，不等于外部已经证明它可行。旧 CLAIMS 自动标签不是新评价的金标准。

对每个 “Which ads” 问题，先固定目标是示例还是完整名单。示例模式可评价返回精确率和证据支持，但不能把它的结果称为全库召回率。

## 4. 可评价范围，单独展示

这些是范围和准备程度，不混入性能成绩：

- 各数据集来源记录数、准入记录数、不同原文身份数及重复／未知日期数量。
- 可读正文覆盖：有经过检查的可用正文记录数 ÷ 准入记录数；另列完整性未知和图片／视频未处理数。
- 原始材料覆盖：有可访问原文、归档或本地快照的记录数 ÷ 所检查记录数，写明检查时间与样本范围；有 URL 不等于已访问成功。
- 标注与评审覆盖：计划任务数、已运行数、已审查数、等待材料数、无效运行数，分列 native／social／cross。
- 历史标签和已发布 CLAIMS 的审查状态。没有已发布匹配不能解释为“没有主张”。

## 5. 如何执行评价

### A. 固定任务与数据口径

客户／领域审核人确认：计数单位、重复规则、实体合并、关系含义、日期和未知状态规则、24 题编码定义、示例／全量名单目标、每个用户任务的时间限制及验收门槛。未指定的负责人、日期和门槛写待定，不代替客户批准。

每个案例保存：`case_id`、需求 ID、数据集、语言、任务类型、输入和筛选、参考完整记录集合或语义成员集合、支持与限制原句、排除理由、必需回答点、预期应答状态和评分规则。

### B. 建立参考答案

统计与关系从被冻结的来源记录独立枚举，不能把被测函数的返回值复制成参考。抽查源文件，确认导入和身份映射本身没有问题。

内容任务由具名领域审阅者读取完整上下文。试点采用两人独立判断并记录分歧，再裁决；正式审核范围与负责人在计划中明确。审查表绑定 `run_id + case_id + 答案版本`，不能把旧答案的评语迁移到新生成答案。

先建立可完整审查的评价子库；召回率只针对这个公开说明的范围。对该范围逐篇确定相关、无关或尚不确定，不能只标搜索返回的文章。减少人工的办法是一次审查正文、复用多个问题的证据矩阵，并集中处理分歧；不是把未返回文章自动记为无关。

### C. 留出与冻结

当前 24 题已经参与设计，是已见的开发问题。统计、关系和图谱可在当前冻结集合上，通过独立枚举和实际操作审查验收；这评价的是当前集合的交付能力。内容跨文章泛化才要求未参与调参的文章组，同稿、转载和近重复属于同组；只改写已见问题不足以证明泛化。没有未见文章组时，可以报告“现有集合上的独立审核”，跨文章泛化继续待评价。按公司、媒体、日期／未知日期、长度、质量状态及任务难度分层，公开抽样方式和种子。

分别保存开发、客户已见和独立检验结果。冻结代码、模型设置、提示词、原文／数据／索引版本、题集、编码规则、参考答案和评分标准的散列。冻结检查证明版本绑定，不自动证明审阅者真的批准或标准答案正确。

### D. 执行真实路径

统计题走实际提问和工具选择；图谱题实际选择节点／边；内容题走实际检索、生成和引用；用户任务观察实际页面操作。后台函数正确不能代替前端任务正确。

预先确定模型预算、并发、超时、重试次数和随机性重复次数。保留所有首次与重复结果，不用“重试成功”覆盖失败。运行时数据／索引漂移则整次运行无效，单独列出，不评分为成功或静默删除。

### E. 评分与不确定性

在有固定参考且已执行的任务中，错误、超时和错误拒答留在端到端分母。未运行／待金标准／待审查另列，不能被隐藏。部分审查可以显示有标记的已审子集结果，但最终成绩保持待审。

独立二元任务可报告 Wilson 95% 区间；它反映有限样本的不确定性，不证明样本代表所有用户。有关联的文章、多个陈述或同一用户的重复任务不能直接当独立样本；正式区间应按文章组／用户组重采样，或明确不提供推断区间。[NIST 区间方法](https://www.itl.nist.gov/div898/handbook/prc/section2/prc241.htm)

P95 使用排序后第 `ceil(0.95*n)` 个时间值；小样本下它可能等于最大值，必须显示 n。旧评价器的 `latency_ms` 是服务器调用耗时，不含浏览器渲染；不得冒充完整页面等待时间。

### F. 发布与更新

正式公开结果必须绑定本次运行和独立审查记录，显示失败、范围、版本、时间及门槛批准状态。不同版本结果标“历史结果”，不能作为当前系统成绩。发版修改数据、提示词或功能后重新评价相关任务，保留旧报告。

验收采用各项必要条件和事先同意的门槛，不以一个加权总分掩盖严重错误。统计任务单题通过必须完全一致；引用伪造、筛选越界和来源混淆应作为阻断项。没有得到客户同意，不宣布统一 90% 或 95% 已成为验收标准。

## 6. 缺失信息的预期行为

| 情况 | 正确行为 |
| --- | --- |
| 本地没有足够支持 | 明确本地证据不足；可按已启用的策略检索外部来源，单独标明未进入集合统计 |
| 实体或范围歧义 | 给出可选来源实体或要求补充范围，不能悄悄合并 |
| 分类结果缺失／未审查 | 说明尚未建立分类结果，不能输出阴性判断 |
| 数据集未接入／正文缺失 | 说明范围缺口，不能称该领域不存在广告或主张 |
| 工具、网络或模型失败 | 显示服务失败；不能当成正确的“没有证据”答案 |
| 已有充分支持却拒答 | 记入 M12，同时 M01 不通过 |

## 7. 已实现与尚未完成

已实现：16 个指标的公共定义、六个需求的映射、Evaluation 页面、未知成绩显示，以及二元结果、集合比较和等待时间的离线算术函数。新增[报告契约](customer_metric_report.md)检查运行、答案、参考、来源与审核绑定；页面支持服务端显式指定文件、文件 SHA-256 和另行冻结的计划 SHA-256。只显示聚合、范围、日期和审核方法，不自动展示原始答案或个人审核信息。没有新增依赖或付费评价调用。

已准备的独立统计参考覆盖当前集合的完整矩阵、关系、年份并列和两个明确时段，带支持记录 ID；[准备方法](../data/statistics_reference.md)不复用生产统计函数。它仍是未批准口径下的开发参考，尚不能当作实际模型提问路径的质量成绩。

已完成一次实际只读工具对账：160格完整成员、35条关系、53页图谱和29个日期范围通过1,844个工程断言，前后来源、索引和账本未变。该检查没有调用模型或操作浏览器，所以不能直接发布M01、M02或M05成绩；真实提问及点选仍按上述方法另行评价。
