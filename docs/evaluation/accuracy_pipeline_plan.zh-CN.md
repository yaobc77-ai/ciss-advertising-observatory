# 回答准确率：本轮改动与下一步

日期：2026-10-07，纽约时间。来源：用户U22；这是工程改进安排，不新增客户要求。

## 1. 先说明结果

已在本机修改提示词、引用处理、MCP工具返回和正文质量传递。**114项选定免费检查通过**，另有真实数据库只读审计及3篇文章的查询验证。付费模型调用0，数据库写入0，未推送、部署或重启网页。

这些结果证明程序约束生效，**尚不能证明模型回答准确率提高**。具名人工审核和客户验收仍未完成。

## 2. 已经做了什么

| 方向 | 通用改动 | 怎么检查 | 仍然不能保证什么 |
| --- | --- | --- | --- |
| 提示词 | 路由规则与证据写作规则分开；写作前检查谁说、谁做、条件修饰哪个动作，保留计划／估计／已实现及否定范围 | 新合成开发材料；实际生成请求的脚本检查；提示版本v6 | 模型一定理解关系或措辞正确 |
| 引用 | 同一来源、版本、位置的相同引用复用编号；摘要、分节和每个论断的编号一起更新；“证据不足”不能夹带生成内容 | 改前9失败／4通过，改后13通过；改前回执已修正两处夹具错误，初始错误记录保留 | 原句存在就一定支持改写 |
| MCP | 核心目录公开最小输出schema；拒绝错误工具名、未知状态、非有限JSON及不规范筛选类型；文字与结构化返回同一份结果 | 官方SDK注册回调的7项独立检查 | 每条业务返回的完整字段和语义已被schema覆盖 |
| 查询状态 | 区分完整检索过程、部分过程、正常空结果与失败；正常空结果才可按规则发放一次联网票据；失败不冒充未命中 | 新脚本复现及13项状态／票据检查 | 正常空结果证明全库没有答案；网页所有重检索路径都有相同票据约束 |
| 来源选择 | 原始字段读取前先查找记录；随后绑定记录／版本。当前范围只有一个可信ID时可直接读取 | 8项选择链检查及最初失败复现 | 模型查找的标题和请求字段一定忠于问题 |
| 失败处理 | 网页保留服务失败、澄清和完整性错误，不把它们改成付费联网补答 | 改前7失败／1通过，改后8通过 | 任何付费联网结果都适合充当本库统计或原件字段 |
| 正文质量 | 当前原生正文的部分提取／疑似截断标记进入模型输入；已恢复正文的旧CSV标记不混入当前状态 | 9项检查；3篇真实文章走生产查询并核对版本与字符位置 | 全文完整性或标签语义正确 |

MCP输出schema是格式约束。本轮采用协议中的可选能力；先前没有公开输出schema本身不构成协议违规。[MCP工具规范](https://modelcontextprotocol.io/specification/2025-11-25/server/tools)

16题覆盖条件归属、主体、数量与状态、否定、转述、缺资料、比较和社交付费身份，共8组对照。它们是小规模开发诊断，不是足够代表真实用户总体的训练集，也不用于声称总体准确率。

下一轮评分分三层：工具／参数和范围是否正确；检索是否找到审定相关来源；改写是否被引用支持且答全问题。生成同时报告“正确题数／全部题数”和“正确题数／已答题数”，缺项与弃答保留，避免靠拒答提高表面成绩。
