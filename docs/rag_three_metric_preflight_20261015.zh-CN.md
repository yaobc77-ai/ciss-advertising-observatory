### 日志与抽取口径

- `server/events.jsonl` 保存了完整 `provider_request.request`、`provider_response`、`generation_context`、`record_selection`、`answer_start` 和 `answer_result`。使用当时保存的 SDK 输入，不用今日源码或今日数据库倒推旧上下文。
- 回答包括保存的 `summary[].text`、`sections[].title` 和 `answer`；只评 `answer` 会漏掉用户实际看到的摘要。这里按固定顺序用空行连接，是评分文本表示，不声称逐字复现 HTML。
- **Context Precision 这次的明确对象是“送入普通写作模型的有序上下文”。** 每题的多次检索包含规划预览、正式查询及多个范围，不能拼在一起当作一份检索排名。每个证据对象保留原顺序。名单筛查的分批枚举需另定阶段和汇总规则，不能默认为普通检索排序。
- 普通 Faithfulness 使用该次写作的实际证据。名单 Faithfulness 使用系统各筛查批次实际看到的证据并集，检查最终程序合成名单的支持性；它不是最终写作模型的单个输入。这两种路径分别报分。
- 有 26 个涉及外部联网的路径，服务端没有保存外部工具内部读取的全部材料，因此严格的整答 Faithfulness 暂不覆盖这些路径。URL 或短引用不能替代完整上下文。
- SQL／字段模板回答、确定性名单、澄清及没有证据的回答按适用性单列，不凭空构造生成上下文。941 个 Faithfulness 候选中有 24 个普通写作的证据不足回答；未来若无法抽取可判定事实，应记 N/A 并报告分母，不能自动给满分。

## 3. 免费测量与计价假设

采用当前官方公开的 `gpt-5.6-luna` 标准同步价格：输入 **$0.20/百万 tokens**、输出 **$1.20/百万 tokens**；`text-embedding-3-small` **$0.02/百万 tokens**。不计缓存或 Batch 折扣。定价核实于 2026-10-15。[模型价格与上下文规则](https://developers.openai.com/api/docs/models/gpt-5.6-luna)、[embedding 价格](https://developers.openai.com/api/docs/models/text-embedding-3-small)。

预算情景明确设为 **reasoning effort=none、每项一次、无失败重试**；这不是已校准的评委设置。模型默认为 medium，若未显式设定，下面预算不能直接沿用。Reasoning 计入输出收费；历史 usage.output_tokens 已包含的 reasoning 不再重复加费。[官方说明](https://developers.openai.com/api/docs/guides/reasoning)。

RAGAS 官方源码固定为 commit `298b68274234c060deacab3cf5fb52aa3a20e885`。离线计数使用 `o200k_base`，包含真实已存问题、摘要／正文、上下文及官方提示。另加输出 schema 代理及每次 64 tokens 的消息封装余量；这些额外项是估算，不是实测 API 序列化。

- Context Precision：每个证据对象 1 次 LLM；可见输出按 256 tokens/次估算。
- Faithfulness：每题拆陈述 1 次 + 集中证据支持判断 1 次；回答长度为 A 时，输出分别按 `ceil(1.5*A)+128` 和 `ceil(3*A)+256` 估算。后一步输入另加第一步生成的陈述估算量。
- Answer Relevance：保留 RAGAS 默认 strictness=3，即每题 3 次 LLM；每次输出按 128 tokens。另计每题 2 次 embedding 请求、4 条文本。
- 上述输出是规划假设，不是已观测用量或硬上限。30% 预留也不是保证；后续实际执行须明确总金额上限、每次 completion 限额、重试与失败停止规则。
- 最大估算单次输入约 **190,453 tokens**，低于该模型 **272,000** 的长上下文加价阈值。若后续追加参考或拆分规则改变，应重新计数。

Embedding 另有 2,544 次 HTTP 请求，规划输入 520,041 tokens；已计入相关性费用。加 30% 余量为 **$6.09**，下一轮可按 **$7** 量级规划。仅原始 B1K 的 996 有效题对应普通三项费用约 **$3.72**、含余量约 **$4.84**。

**A 的可选扩展：名单最终答案证据支持诊断。** 495 题按各筛查批次真实证据的并集做支持判断，单独报分。预估另需 990 次 LLM、17,781,609 输入 tokens、1,595,131 输出 tokens，约 **$5.47**。与 A 合计 **$10.16**、含 30% 余量 **$13.20**，可按 **$15** 量级规划。这部分使用 Faithfulness 的判定方法，但指标对象是系统多阶段合成答案，不能称普通写作模型的标准 Faithfulness 或与其直接混合。此处尚未授权任何预算。

Reasoning 敏感性：若每次 LLM 评分额外消耗 1,024 reasoning tokens，A 加名单诊断的 7,773 次请求就会多约 **$9.55**；4,096 则多约 **$38.21**。这是情景计算，不能据此预测默认 medium 的真实用量。

### B. 补齐参考及阶段口径后的扩展情景

若将 Context Precision 扩展至本地普通写作／名单筛查的非无答案路径，候选为 **925 题、20,420 个上下文对象**。这是进一步准备后的预算情景，不是目前已有 925 题可直接评分。

- 对尚未构造的参考，假设每次携带 256–1,024 tokens；对未知序列化额外留 10% 上下文余量。
- CP 约 **$15.85–18.64**；加同范围已具备资料的 Faithfulness、Answer Relevance，总计 **$24.42–27.21**。
- 加 30% 余量为 **$31.74–35.37**；可把 **$36** 作为进一步计划的预算量级，不能现在宣称硬上限足够或已经准备好运行。
- 扩展情景共有 26,118 次 LLM 请求；若每次另用 1,024 reasoning tokens，会再增加约 $32.09，因此 30% 余量不能掩盖未固定的 reasoning 配置。
- 这一情景仍不包含旧题集、补跑模型答案、恢复外部网页完整上下文、额外模型生成参考或新的人工标注。名单全枚举顺序的 CP 应作为独立阶段诊断，不与普通检索排序混成一个平均分。
