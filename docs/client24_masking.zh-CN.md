# 客户24题：测试与开发隔离

更新：2026-10-07。来源：用户明确要求“客户24题为测试集，严格执行掩码，仅用于测试和评估”。归属：user goal U19；题目本身的客户来源不变。

## 规则

1. 客户24题、参考答案、改写题、逐题结果及题目专用判定规则不进入训练、开发示例、提示词、检索示例或参数选择。
2. 修复使用独立构造的问题和资料。此次例子涉及虚构媒体、日期范围、原始字段和多任务计数，不使用客户题目或答案。
3. 测试前冻结代码、数据、模型、参数、评分规范和费用上限。正式评估逐题提交当前问题，不把整套测试目录或答案提供给被测模型。
4. 看过测试结果后修复过的版本属于后续迭代。旧结果保留，不能据此声称客户24题是独立未见测试。
5. 来源独立的 CLAIMS 分类法、原始文章和元数据可继续使用；不能把测试题目录包装成线上领域知识。

## 已实现的隔离

| 入口 | 当前行为 |
|---|---|
| 一般问答提示与模型输入 | 移除整套客户题目录及题目专用规则；模型只接收当前问题、当前范围和通用工具 |
| 正常 MCP／模型工具 | 不暴露、不允许调用按客户题号读取结果的旧工具；CLAIMS 工具保留 |
| 原题加载 | `evaluation_mask.py` 要求显式本地测试／评估上下文，再验证原题文件 SHA；网页不会进入该上下文 |
| 正常网页 | 隐藏旧客户题目录；不加载题目文字 |
| 开发测试收集 | 在导入前隔离已知题目依赖模块；旧源码和字节码入口均检查 |
| 开发测试读取 | `run_masked_checks.py` 在读取前拒绝原题、参考和旧结果路径，阻止子进程绕开读取守卫，保存读取路径与 SHA |

运行新构造的免费检查：

```powershell
python -X utf8 scripts/run_masked_checks.py --report-dir .runtime/masked-check-new -- tests/test_masked_repair.py tests/test_original_metadata_tools.py -q
```

报告目录必须是新目录。脚本固定使用当前 checkout 的 `src`，避免虚拟环境中的旧 editable 安装被误测。

原题和旧材料没有删除。以后训练／开发候选应单独准备，审核其来源后再使用；现有曾参照客户题准备的候选先隔离，不能直接成为掩码开发集。
