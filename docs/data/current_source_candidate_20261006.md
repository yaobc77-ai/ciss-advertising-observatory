## Reproduce the installed code

Use the [existing installed-wheel procedure](../operations/CURRENT_RELEASE_REPRODUCTION.md).
Export the locked `test` and `mcp` dependencies, create a new virtual environment,
install them, then install the wheel without an editable checkout. Export and
build with an explicit source project. Use a new evidence directory and keep
absolute paths to its requirements file and wheel:

```powershell
uv --project '<source>' export --offline --locked --no-dev --extra test --extra mcp --no-emit-project --output-file '<new evidence>/requirements.locked.txt'
uv --project '<source>' build --wheel --offline --no-python-downloads --out-dir '<new evidence>/wheel'
```

Then change to a clean directory outside the source tree for installation and
verification. Select the one wheel produced by the build:

```powershell
uv venv --offline --no-python-downloads --python '<available Python>' '<new environment>'
uv pip sync --offline --require-hashes --python '<new environment>/Scripts/python.exe' '<new evidence>/requirements.locked.txt'
uv pip install --offline --no-deps --python '<new environment>/Scripts/python.exe' '<candidate wheel>'
& '<new environment>/Scripts/python.exe' -I '<source>/scripts/verify_current_release.py' --source-root '<source>' --wheel '<candidate wheel>' --output '<new receipt>'
```

The offline commands require the dependency and tokenizer caches to be present.
This check does not prove installation on a machine with no cache. Do not add
`--database` for the offline route. Maintenance and preparation commands also
require the source tree's `scripts/` and `eval/`; these are not wheel contents.

## Completion boundaries

Documentation is not universally portable: links to client requirements,
original source files, private runtime evidence, excluded JUnit reports and old
delivery archives require their separately supplied materials. Only exact local
Markdown links whose targets are bundled are converted to relative links.
The source manifest records every archived byte; it does not promise that all
historical or private links are available on another machine.

A passing package check establishes the tested installed code and synthetic
engineering paths. It does not establish real content accuracy, social-ad
admission, new embeddings, complete archive coverage, an independent machine's
restore, production deployment or client acceptance. Those tasks remain in
[plan.md](../../plan.md) and [goal.md](../../goal.md).
