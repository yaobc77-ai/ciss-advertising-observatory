# 视频占位文本：省力处理计划

更新：2026-10-06。状态：**省力计划和素材分流已完成；6份保存页面文字经AI工程审查采用到本机库。实际视频字幕、转写和时间引用仍待办**。

## 执行摘要

目标：先让视频里的主要说法能被找到，并能回到对应时间段；首版不追求逐字准确。

| 决定 | 首版做法 |
| --- | --- |
| 优先路线 | 发布者字幕 → 平台自动字幕 → 有人声时一次小模型转写；结果缓存复用 |
| 减少人工 | 不逐字改稿，每条只抽查开头／中间／结尾；人工最多5分钟 |
| 可以接受 | 普通词、标点、断句及时间戳的小误差；不做逐帧OCR、逐词对齐或精确说话人分离 |
| 回答方式 | 明示“自动字幕／转写，未逐字核对”，给视频链接和时间段；关键含义不清就说明不确定，不补写 |
| 小批停止线 | 最多3条实际广告；每条10分钟音频、15分钟处理。入口失败最多重试一次，超限留待办 |
| 怎样判断有用 | 能检索到主要内容、定位到视频，记录成功／失败、耗时和人工分钟；不以全稿人工校正作为前提 |

字幕／转写结果可先支持探索，不等待整稿人工批准；是否接入公开应用仍按既有发布流程。省力取舍只用于视频文本，不改变文章、统计、来源关联和客户验收标准。详细资源上限、任务状态及未解决事项见下文。

## 首版默认做法

- **先处理拿得到的素材。** 已采用的6份保存页面文字先用于检索。有入口且能对应原广告的视频优先；缺链接、访问失败的记录留待办，继续其他记录。页面文字与视频字幕分别记录。
- **自动文本先用于探索。** 先用现成字幕，没有字幕再对人声音轨做一次小模型转写并缓存；不为追求逐字正确反复换模型，也不让LLM补写或润色听不清的话。
- **只抽查少量片段。** 首批最多3条实际广告，每条检查开头、中间、结尾各一小段。普通转写小错不逐字改稿；关键名称、数字、否定或承诺不清楚时，才复听相应片段，仍不清楚就保留不确定。
- **展示质量和覆盖范围。** 自动结果标为“自动字幕／转写，未逐字核对”，证据给视频链接和起止时间。未处理的片段、画面和失败原因单列；转写成功不等于广告内容完整。

首批记录可搜索的广告数、处理耗时和人工分钟，再决定是否扩展。这里定义的是省力试跑方式，尚无实际转写结果，也没有预先承诺准确率。

## 先复用哪些工具

- [yt-dlp](https://github.com/yt-dlp/yt-dlp#subtitle-options)提供字幕和自动字幕选项；`--skip-download` 可只取相关文件。可用它检查已定位的视频，不自行写各平台下载器。**这些媒体实际能否提取字幕，仍须试跑。**
- [faster-whisper](https://github.com/SYSTRAN/faster-whisper#usage)支持CPU INT8转写，输出带时间段的片段，并支持过滤无语音区间。拟作为无字幕时的备选，先试英文小模型和快速解码参数，速度与误差需要在本机测量。
- 已复用本机[FFprobe](https://ffmpeg.org/ffprobe.html) 8.1.1检查3个MP4的音轨与容器信息，不另造媒体解析器。远程探测读取部分媒体字节；没有保存音视频文件，实际读取量未计量。

yt-dlp和faster-whisper是候选工具，不是当前生产技术栈。2026-10-06本机项目环境尚未安装这两个包；本轮没有安装包、下载模型、保存音视频或调用付费API。

字幕试跑使用明确的视频入口，禁用默认配置和插件，不使用账号／cookies。每种重试上限设为1，外层进程另限60–90秒；网络等待超时不是总时限。多个嵌入限制为一项，但必须先确认所选项属于目标广告。CNBC的专用提取器主要匹配`/video/...html`，普通MP4也不会自动产生外部字幕，不能因工具支持媒体名就宣称这批广告可用。[官方README](https://github.com/yt-dlp/yt-dlp)、[CNBC提取器](https://github.com/yt-dlp/yt-dlp/blob/master/yt_dlp/extractor/cnbc.py)、[Generic提取器](https://github.com/yt-dlp/yt-dlp/blob/master/yt_dlp/extractor/generic.py)。安装后记录实际版本；本轮只核对官方master文档和代码，没有取得发布版号。

## 哪些准确性可以让步

可以接受少量标点、大小写、断句、时间戳偏差和普通词语的转写误差；默认使用未逐字校正的自动字幕／转写做发现与检索。首版暂不做逐帧OCR、画面描述、精确说话人分离或逐词强制对齐。

来源绑定、数量计算和“广告到底说了什么”仍不能靠猜。被答案引用或已发现异常的公司名、数字、否定、承诺与已实现效果，若转写不清楚，答案需标出不确定，必要时只复听相关时间段。不要求人工遍查每个数字或在每次提问时审核；未核验项保留自动转写说明。模型不能补写听不到的话。字幕没有某种说法，不等于整个视频没有；画面文字仍未覆盖。

发布者字幕、平台自动字幕和本机语音转写分别标记。自动转写的字符匹配只证明引文存在于转写文本，不能称为已核实的逐字语音引文；证据卡应给出视频链接、起止时间和“自动转写，未逐字核对”的说明。

## 控制人工和维护量

团队实施建议，尚非客户验收门槛：

1. 先从最多3条广告记录试跑，优先覆盖两家媒体和不同素材条件。记录取字幕成功率、耗时、音轨处理时间、异常与人工分钟数。素材不足时记录原因，不阻断已成功项目；若试跑全部失败，停止调平台参数。
2. 每条试跑只抽查开头、中间、结尾各一段；仅被答案引用或出现异常的关键数字、公司名和否定考虑复听。无需逐字审完整条视频。没有人工检查时保持“自动处理、未核验”，不计作已审核语义成绩。
3. 字幕获取每个入口最多一次重试；失败不循环下载。自动转写同一音轨／模型版本只运行一次，缓存结果。超出试跑资源范围的长视频延期，保留失败和未处理状态。
4. 小批结果可用后再批处理剩余可计数视频。原12条排除记录保留现有计数范围；字幕恢复不自动把它们纳入广告总数。
5. 只有关键来源绑定、异常语句和发布前的必要核对需要人工；不要求人工给所有字幕改稿。

### 首批资源上限

以下是团队的可调整停止线，不是新增客户验收要求；试跑前写入运行记录，达到上限就延期，不能悄悄截断后声称完整。

| 项目 | 默认上限 |
| --- | --- |
| 实际广告数 | 最多3条；同一广告的多个素材合并计算资源 |
| 待处理音频时长 | 每条10分钟，整批30分钟；更长素材暂缓 |
| 保存的音视频量 | 每条50 MiB，整批150 MiB；字幕优先，ASR只取音轨。字幕文件及工具／模型下载另记 |
| 获取音轨至转写输出的墙钟时间 | 每条15分钟，整批45分钟；字幕入口仍按60–90秒外层限时 |
| 人工检查 | 每条最多5分钟，整批15分钟；抽查开头／中间／结尾短片段，有异常只查相关位置 |

逐项结局分为：字幕恢复、转写恢复、保存页面文字已采用／待审、无可用语音、入口缺失、访问失败、身份未确认、超过资源上限。留下结局即可完成分流；页面文字采用与视频恢复分别计数。只有成功且可定位的字幕／转写计入“视频已恢复”，失败不计成功，也不为补齐数量循环重试。

一条广告有多个视频时，先确认主要叙述素材；缓存每个独立片段，并记录未处理的片段。无可用语音的素材保留“无转写”，不转而投入逐帧OCR，也不将处理一个片段表述为整条广告完整覆盖。

## 接入与完成判断
